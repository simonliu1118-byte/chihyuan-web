# AI 代理接口設計（草案，階段 0）

> 狀態：**設計，未實作**（使用者 2026-11-26）。本文件不是規則來源；永久規則以 `REPO_POLICY.md`、`PROJECT_RULES.md` 為準。
> 目的：讓 Grok BOT、GPT 等 AI 代理不經瀏覽器直接操作 CY Web，權限由使用者在「帳號與權限」設定，與員工相同的伺服器端檢查。

## 1. 前提：伺服器端規則盤點（階段 1 之前必做）

代理直接呼叫 API，**所有只在前端的限制對代理無效**（條件鎖定欄位、只在畫面的必填、下拉只列部分選項、依角色隱藏按鈕等）。同樣的缺口任何已登入員工用開發者工具也能繞過，因此這是現有安全問題，不只是代理的問題。

- 開放任何模組給代理前，先完成該模組的**伺服器端規則盤點**：逐一對照前端的鎖定／條件／選項限制，確認伺服器有同等檢查並有測試；沒有就補到伺服器。
- 盤點範圍：全部模組（使用者 2026-11-26 決定由 Claude 於下週額度重置後全面盤點）。結果寫入各模組 contract 文件的「伺服器端規則」段，並在本文件 §8 記錄進度。
- 代理只能呼叫**已完成盤點**的端點（白名單）。

## 2. 代理帳號

- 在「帳號與權限」新增「代理帳號」類型（非 CYID 員工、不能登入網頁、沒有密碼）：名稱、用途說明、負責人（員工）、狀態（啟用／停用）、到期日（選填）。
- 權限沿用模組權限設定：可用模組、每模組「唯讀／可寫」；角色固定為一般使用者，不得為超級管理員。
- 稽核：所有動作記錄 `actor = agent:<id>`，異動紀錄頁可篩選代理。

## 3. 憑證

- 每個代理一組或多組憑證；只顯示一次，伺服器只存雜湊（同 BOT 憑證做法 `bot_credentials`），可輪換、停用、設到期日。
- 以 `Authorization: Bearer` 傳入；憑證放在 AI 平台的安全祕密欄，不得寫入技能檔、提示詞、檔案或聊天。
- 停用或刪除代理 → 所有憑證立即失效（每次請求即時查驗，不快取超過 60 秒）。

## 4. 授權

- 代理請求走**與網頁相同的服務層與檢查**（模組權限、資料檢查、revision 樂觀鎖），不另寫一套；在進入點把代理轉成與員工相同的 principal 型別，加上 `isAgent` 標記。
- 端點白名單：只有標記為 agent-enabled 且已盤點的端點可用；其餘一律 403。
- **永不開放給代理**（只能由人操作）：薪資確認／標記已發薪／撤回、身分證完整號碼、任何刪除、備份與還原、帳號與權限設定、系統與安全設定、CYID 相關、匯出全量資料。

## 5. 寫入（階段 3）

- 預設：代理的新增／修改先成為「待確認」項目，由負責人或主管在 CY Web 確認後才生效（類似 BOT 審稿）。
- 使用者可逐項開放「直接生效」（例如新增工作日誌草稿）。
- 待確認項目保存原請求、代理、時間；確認時重新跑完整伺服器檢查，不沿用代理送出時的結果。

## 6. 限量與資料保護

- 每代理每分鐘請求數上限、每次查詢筆數上限（例如 50），不提供批次全量匯出。
- 個資欄位（身分證、住址、電話等）預設不回傳，需逐欄開放。
- **提示注入**：代理讀到的客戶備註、留言內容可能含有指令；權限最小化與 §4 高風險清單是主要防線，不依賴代理自律。
- 一鍵停用：任何代理可立即撤銷。

## 7. 介面形式

- REST：`/api/agent/v1/...`，回應格式沿用 `API_CONTRACT.md`。
- MCP（選用）：以 Workers 提供遠端 MCP 伺服器，工具對應 REST 白名單端點，供支援 MCP 的平台（GPT、Claude 等）使用；不支援者用技能包＋命令工具（同 Grok 小編）。
