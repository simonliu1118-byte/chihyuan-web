# 出機紀錄與定期維護

本契約依使用者 2026-11-05 確認的設計與後續更正；不是新的永久治理來源。

## 介面與權限

門市的「售後維修」使用既有 `SegmentedControl`，同層切換「門市送修／出機紀錄／定期維護」。不再往下疊頁面切換。三個檢視沿用 `STORE_REPAIRS` 使用權，所有 API 均由後端驗證；不新增另一套 Identity 或模組權限。

出機清單採共用密集表格、斑馬紋、操作圖示及可收合的機身資料／操作紀錄。新增修改用 `EntryTable`、`Field` 與 `DateInput`。維護矩陣使用共用 IconButton（圓圈／警示）及 `StoreMilestoneButton` 日期戳記；編輯使用 `StoreMilestoneDateFields`（allowWithoutDate=false）、DateInput、單行 Field、既有 `.cy-store-date-popover` 和確認元件。沒有新增另一組日期選擇器。

## 出機資料

一筆代表同一客戶、品牌、機型及同次銷售的一批機器：

- 第一列同時放客戶編號（可空）、客戶名稱（必填）、品牌、機型、銷售日期、數量。
- 第二列表頭為保固期間（起日～訖日同格）、保固月數、定期維護。起日＋月數直接以日曆月份推算同日的迄日，例如 5/15＋3 月＝8/15；目標月份無同日則落到該月最後一天。填起訖日則用日曆月差無條件進位至整數月；最後修改月數或迄日者為準，修改起日時沿用該計算方向。
- 定期維護改為「需保養維護／無須保養維護」互斥單選；新增時未選，修改時沿用儲存值。資料欄位仍是既有 maintenance boolean，不新增資料表。
- 機身序號與製造年月的表頭、表身直接接在出機表單下方，不另包內層表格、不顯示「機身資料 N 台」欄。製造年月由共用 DateInput 的 YYYY/MM 年月模式選擇，API 仍儲存 YYYY-MM；筆數與數量一致，非空序號不得重複。
- 預計年月清單與每半年帶入工具保留原邏輯；實際日期不會推動後續月份。

客戶編號會 trim、NFKC 正規化及轉大寫，作為同客戶彙整鍵。**不填編號時固定不需維護**，控制項停用並以 tooltip 提示「請先填寫客戶編號，才能啟用定期維護」；後端同樣拒絕無編號啟用或不需維護卻帶排程。清除編號會清除草稿維護選擇，不會刪除已完成到訪。

需維護時必須具備保固起訖及至少一個預計年月；月份須落在保固涵蓋月份內。跨年保留年份。銷售日及製造年月不能晚於今天／本月。傳輸上限 1 MiB；長度共用 `EQUIPMENT_LIMITS`，數量最多 1000、保固跨度及選擇月份最多 600 月（50年），避免無界表單與請求。

## 維護彙整

一個「正規化客戶編號＋預計年月」只有一筆到訪。同客戶同月份有多筆出機時，彙整機型與數量，展開可查看來源；不逐台檢核，只登記此次已前往。原出機仍保留各台序號及製造年月。

### 三年橫向矩陣（V0.11.1）

一客戶一列，左側固定項次與客戶編號／名稱；右側固定操作紀錄。橫向第一層表頭是年、第二層是1–12月，預設上一年／今年／下一年（2026年即2025–2027）。可往前後移一年、回到今年，或搜尋／顯示未完成；預設全部。窄螢幕在表格內橫向捲動，頁面本身不溢出。出機資料可在客戶欄展開。

- 預計當月或未來：空心圓；台灣時間進入隔月仍未完成：三角驚嘆號。每天及視窗恢復焦點時僅更新本機日期，不輪詢API。
- 圓圈／警示可點入實際維護日期及最多300字的單行備註。**實際日期必填，不支援無日期，也不得晚於今天**；沿用日期欄紅框與Enter跳到備註、再Enter儲存。
- 完成日期放在實際年月。跨月完成時，原計畫月保留上下兩行「→」「8月」等去向（小字置中、固定24px高，不撐高列），滑過可見完整預計／實際年月日；原警示解除，沒有建立第二筆到訪。
- 同客戶同實際日期的不同計畫合併成一個日期，不顯示筆數標記；點開列出各筆預計年月、日期、備註，仍可分別修改。不同實際日期在同月格分行，允許列高增加。未完成的其他安排不被已完成日期遮掉。
- 實際日期在三年內，即使原計畫在範圍外仍會列出；原計畫在範圍內但實際在範圍外，仍保留去向及編輯入口。
- 既有已完成但無日期的資料原樣保存，在原計畫月顯示「補日」；不自動猜填日期。新登記與更正都必須有日期。取消登記則回到原計畫的圓圈／逾期警示。

這不是維修結案，不套五分鐘關閉或月度待辦次月16日截止規則。

### 保留歷史與多人操作

- 未完成的月份隨出機排程變更即時彙整；不需 cron 或每月預建空白列。
- 完成時固定當時涵蓋的出機摘要；後續修改機型、數量、客戶或取消排程，已完成日期與備註仍保留。
- 完成前已移出排程的出機，不會被補進歷史摘要。
- 若要把新出機加入已完成到訪，後端拒絕整次新增／修改。需先取消該到訪登記再調整，避免新機器被默認為已維護。
- 出機及到訪均有版本；任何涵蓋內容變動會使已開啟的未完成到訪編輯器失效，須重新整理。全域版本 guard 與資料／排程／事件／Audit 在一個 D1 batch 中提交，失敗全部 rollback。
- 同使用者 requestKey 唯一並核對 request hash；重試同操作不重複寫入，不同內容不能共用識別。

## API

根路徑 `/api/business/store/equipment`，回傳沿用 API envelope。

| 方法與路徑 | 功能 |
| --- | --- |
| `GET /` | 出機清單，q 搜尋客戶／品牌／型號／序號，before 使用 list_sequence 游標 |
| `POST /` | 新增，requestKey＋出機欄位 |
| `GET /:id` | 單筆完整機身資料 |
| `PUT /:id` | 修改，expectedVersion＋requestKey＋完整欄位 |
| `GET /:id/history` | 延遲載入出機歷程，cursor 向前翻頁 |
| `GET /matrix` | year為中心年；q／open=1／before客戶碼；50客戶一頁，完整帶回視窗內相關計畫與實際日期 |
| `GET /customers/:code/history` | 該客戶所有維護操作紀錄，附預計年月，cursor分頁 |
| `GET /visits` | 彙整清單，q／year／open=1／before（月＋id） |
| `GET /visits/:id` | 單筆到訪與涵蓋出機摘要 |
| `PUT /visits/:id` | expectedVersion、requestKey、completed、completionDate（completed=true必填；取消登記時null）、note |
| `GET /visits/:id/history` | 到訪操作歷程 |

出機／舊到訪API每頁100筆；矩陣每頁50客戶（各客戶的相關月份完整載入），歷程每頁50筆，多取1筆判斷下一頁，使用 keyset 與索引。出機清單不攜帶機身序號陣列，展開／修改才讀單筆並於目前清單重用；序號仍可搜尋。矩陣用三個集合查詢讀客戶、相關月份及去重的保留來源摘要，沒有每格或每月一個請求；維護／客戶年月及實際日期使用索引。歷程沿用 bounded LRU、展開才讀，不預抓全部歷程。不新增背景輪詢，業務 GET 不寫入排程。儲存成功直接套用單筆回應，沒有重抓整張清單。

## 資料與備份

Forward migration `0051_store_equipment_maintenance`：

| 表 | 用途 |
| --- | --- |
| store_equipment_records | 出機主檔、序號陣列、版本與時間／操作者 |
| store_maintenance_visits | 客戶＋預計年月唯一到訪、完成狀態、日期與單行備註 |
| store_equipment_plans | 出機與到訪的關聯、目前排程 active、完成時保留 retained 與摘要快照 |
| store_equipment_events | 二擇一出機／到訪歷程，requestKey／hash、精簡前後值與操作者 |
| store_equipment_state | 首次修改才建立的單列版本 guard，協調彙整原子修改 |

所有表納入 portable backup 的欄位清單；CURRENT_MIGRATION 同步0052（0052只增加維護客戶及實際日期索引）。純新增表不需資料語意轉換，舊備份缺表還原為空；表與關聯、完成日期、單行備註及歷程有還原 round-trip 驗證。照片、R2、Identity、既有排程及正式資料皆未改動。
