# BD-043 — CY Web configuration authority is split between Super Admin and Admin

**Status:** CONFIRMED

## Decision

CY Web keeps the current three account levels from the shared Identity authority:

- regular user;
- Admin;
- Super Admin (SA).

CY Web does not introduce a more granular RBAC model at this stage.

Configuration authority is intentionally split so that day-to-day administrators can manage WorkLog operating parameters without being able to casually change lower-level application structure.

## Super Admin-only configuration

Only SA may manage the following CY Web application configuration:

- customer categories;
- departments;
- customer statuses;
- item categories;
- CY Web app tags and the module-access mapping associated with those tags.

These settings affect broad application structure, classification, or access and therefore are not ordinary Admin-maintained parameters.

Admin must not be able to create, rename, reorder, deactivate, delete, or otherwise change these SA-only settings.

SA may also perform the Admin-level configuration described below.

## Admin-manageable WorkLog configuration

Admin may manage the operational WorkLog parameters that are expected to change as normal business practice evolves:

- WorkLog items/categories;
- WorkLog platforms/channels;
- WorkLog scoring/reference points;
- WorkLog target/minimum average daily score and related scoring parameters.

SA may manage these values as well.

Regular users do not manage either configuration layer.

## Identity boundary

`Super Admin` and `Admin` come from the shared CYInvoice-compatible Identity/account authority. CY Web must not recreate independent global Admin/Super Admin identities.

CY Web-specific tags such as sales/staff/warehouse/designer remain application metadata used for module access. The ability to configure those tags and their module-access mapping is SA-only.

## Enforcement

The UI should hide or disable configuration actions the current account level cannot use, but the authoritative check must be performed by the CY Web server/API.

An Admin request attempting to modify SA-only configuration must be rejected even if it is submitted outside the normal UI.

Configuration changes should continue to produce structured audit events with actor, timestamp, and before/after values.

## Future extension

If a dedicated maintenance/IT role is introduced later, some SA-only configuration responsibilities may be delegated through a separately approved authorization change. Until then, the three-level model remains intentionally simple and the lower-level configuration authority stays with SA.
