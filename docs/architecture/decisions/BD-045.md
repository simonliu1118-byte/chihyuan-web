# BD-045 — Chihyuan production backup uses GCS through a provider-neutral contract

**Status:** CONFIRMED

## Decision

For Chihyuan production deployments, the initial off-site backup provider for CY Web is **Google Cloud Storage (GCS)**.

Cloudflare D1 remains the live application database. GCS is used as an external backup/recovery target so that production data and disaster-recovery copies are not kept solely inside the same Cloudflare provider boundary.

Public source remains provider-neutral and depends on a generic `BACKUP_PROVIDER` contract. Selecting GCS for Chihyuan production must not hard-code Chihyuan bucket names, project IDs, service identities, credentials, or other production resource identifiers into the public repository.

## Coordination with CYAccountingWeb

CY Web and CYAccountingWeb should align on the same backup-provider contract and, where practical, the same portable package / manifest / checksum conventions.

During the current independent-deployment stage:

- the two applications may use the same Google Cloud project;
- each application keeps a separate backup dataset, using a separate bucket or otherwise strongly isolated namespace;
- each application uses its own least-privilege service identity / credential;
- one application's credential must not grant access to the other application's backup dataset;
- each application's database remains independently restorable.

Do not solve future product integration by sharing one broad GCS key across both applications now.

## Future shared Backup Service

If CYAccountingWeb is later integrated into the Chihyuan Enterprise Management System as an accounting module, the preferred evolution is to extract a shared CY Backup Service / Backup Worker:

```text
CY Web ---------┐
CYAccounting ---+--> CY Backup Service / Worker --> GCS
future apps ----┘
```

At that stage, individual applications should call the backup service through an internal service/API boundary, and only the backup service should need direct GCS authorization. Per-application direct GCS credentials can then be retired.

Even after service consolidation, CY Web and Accounting backup sets remain logically separated and independently restorable; they are not combined into one mixed backup file merely because they share a backup service.

## Provider contract

The shared contract should cover at least the following capabilities, with exact TypeScript naming finalized during implementation:

- create backup;
- list available backups;
- verify backup integrity;
- restore a selected backup;
- apply retention / delete expired backups.

The portable backup package should include sufficient metadata for safe verification and restore, such as application/schema version, creation time, row counts or equivalent record counts, manifest information, and SHA-256 integrity data.

## Security and deployment

Google Cloud project identifiers, bucket names, service-account / workload-identity details, credentials and secrets are deployment-specific infrastructure and must be injected through protected deployment/runtime configuration.

Use least privilege. Prefer authentication that avoids unnecessary long-lived credentials where practical; the exact GCS authentication mechanism is an implementation decision and does not change this business/architecture boundary.

## Backup / restore authority

BD-044 remains authoritative for in-app operation:

- backup and restore are Super Admin-only;
- restore requires double confirmation;
- restore and backup actions are server-authorized and audited.

## CYAccountingWeb transition note

CYAccountingWeb V0.16.0 already contains reusable concepts for D1 portable JSON packaging, counts, SHA-256 verification, retention and scheduled backup, but its current storage implementation targets Google Drive.

When CYAccountingWeb adopts this architecture, preserve the reusable package / integrity / schedule logic where appropriate and replace the final storage-provider / authentication layer with the GCS provider contract rather than treating Google Drive as the long-term Chihyuan production backup target.
