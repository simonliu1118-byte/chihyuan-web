# BD-021 — Customer-item quote history preserves Legacy usage semantics

**Status:** CONFIRMED

## Decision

CY Web preserves the successful Legacy business behavior for customer-item quotation history instead of redesigning it into a formal quotation-document workflow.

Each quotation-history record represents one customer plus one item and may contain multiple quantity-price break rows.

Core usage semantics to preserve:

- one quotation-history record = one customer + one item;
- each record may contain multiple quantity / unit / unit-price / note break rows;
- quotation date and salesperson/employee context are retained;
- a new quotation for the same customer + item creates a new historical record rather than overwriting the previous record;
- prior quotation records remain available for chronological lookup and price-comparison history;
- the latest quotation may be surfaced as the primary/default reference for future lookup or data entry, but it does not replace or mutate older records.

This preserves the practical value of the Legacy flow: sales staff can quickly see what price was quoted previously, when it changed, who quoted it, and how quantity breaks differed over time.

## Canonical normalization boundary

The user-facing workflow should remain familiar to the Legacy version, but the underlying data model should be normalized.

The canonical implementation should therefore:

- reference stable `customer_id` and `item_id` relations;
- avoid using copied customer/item names or item numbers as foreign keys;
- store quotation-history identity independently from display/business identifiers;
- normalize quantity-price breaks into child rows rather than one opaque JSON field when the final schema is implemented;
- preserve only intentional historical snapshots where needed for reproducible history.

Legacy technical identifiers such as `quoteId = custId + Q + sequence` are migration traceability details, not a requirement for CY Web's new internal primary-key format.

## SMART ERP boundary

BD-020 remains authoritative: these records are lightweight customer-item quotation/price history only. Formal quotation documents belong to SMART ERP and are not recreated in CY Web.

## Migration implication

Legacy `Quotes` rows should migrate as distinct historical quotation records. Multiple rows for the same customer and item must not be collapsed into one current value merely because the relation matches.

Legacy `details` quantity-price rows should be migrated in order, preserving quantity, unit, quoted price and note where recoverable.
