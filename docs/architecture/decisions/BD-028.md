# BD-028 — Resolved defect reports may be reopened through an explicit status transition

**Status:** CONFIRMED

## Decision

A defect report that has reached:

```text
resolved / 已處理
```

may be reopened to:

```text
processing / 處理中
```

when the same underlying defect case was not actually finished or requires additional handling.

This must be an explicit business action such as **重新開啟**, not an unrestricted free-form status-field edit.

## Same case vs new case

Use reopening when the same defect case continues, for example:

- the customer reports that the original handling did not fully resolve the issue;
- additional follow-up is required for the same reported defect;
- the original case was closed prematurely.

Create a new defect report when the event is substantively new, for example:

- a different shipment or batch;
- a separate independent defect occurrence;
- a new customer complaint that should have its own lifecycle.

The system must not collapse independent defect incidents into one indefinitely reopened record.

## History / audit semantics

Legacy Desktop already records defect status transitions in the report's domain `logs`, including actor/date and the status action. CY Web preserves this existing business-traceability semantic rather than adding a second redundant audit mechanism solely for reopening.

In the target model, the transition should be represented as structured domain history/audit so the same event can support both user-visible history and administrative traceability. At minimum the event records:

- defect-report reference;
- actor;
- event time;
- previous status (`resolved`);
- new status (`processing`);
- action/event type (`reopened`).

Whether a mandatory reason is required is not fixed by this decision and may be decided with the final high-risk/correction UX policy.

## Workflow implication

The canonical defect lifecycle therefore supports at least:

```text
created / 已建檔
        ↓
processing / 處理中
        ↓
resolved / 已處理
        ↓ explicit reopen
processing / 處理中
```

Normal forward status actions and reopen actions remain business events with preserved history.

## Migration implication

Existing Legacy defect `logs` and workflow state should be migrated as historical domain facts where reliable. Ordinary non-status field edits in Legacy were not comprehensively versioned; CY Web may improve that audit coverage separately.
