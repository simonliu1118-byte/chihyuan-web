# BD-056 — `chihyuancm.com` is the shared parent domain for public and internal Chihyuan Web systems

- **Status:** CONFIRMED
- **Scope:** Chihyuan domain namespace / CY Web rollout

## Decision

`chihyuancm.com` is the confirmed parent domain for both:

1. the future public Chihyuan official website; and
2. Chihyuan internal/business Web systems, including CY Web and other CY-family applications.

The domain is already registered through Cloudflare Registrar. The initial registration term is one year; future renewals may remain annual or be extended to a multi-year term as appropriate. Registration-term length is an operational choice and does not change the domain architecture.

Using one parent domain does not collapse the systems into one origin or one security boundary. Public and internal systems use separate hostnames/subdomains, deployments, sessions and authorization boundaries.

## Namespace baseline

Current planning baseline:

```text
chihyuancm.com                 Official public website
www.chihyuancm.com             Website alias / redirect
admin.chihyuancm.com           CY Web / enterprise management
accounting.chihyuancm.com      CYAccountingWeb
invoice.chihyuancm.com         CYInvoice Web
auth.chihyuancm.com            Shared identity / future CYCloud Identity
portal.chihyuancm.com          Future unified portal when needed
api.chihyuancm.com             Reserved for genuinely shared API/services when needed
```

The exact set of active subdomains may evolve as applications become production-ready, but the parent-domain strategy remains fixed unless explicitly changed later.

## Security boundary

- Keep application sessions host-scoped by default.
- Do not share cookies across `.chihyuancm.com` merely because systems share the same parent domain.
- Shared SSO, if introduced, is implemented explicitly through the Identity boundary.
- The public website and internal systems remain separately deployable and independently protected.
- Internal/high-risk systems may use stronger access controls where appropriate.

## Rollout timing

The namespace is decided now, but production DNS/custom-domain binding is not an early-development prerequisite.

Actual hostname binding should occur during controlled production rollout when the target application, Identity/session behavior and major workflows are ready for acceptance.
