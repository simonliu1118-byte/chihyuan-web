# BD-033 — Defect record edit and deletion boundaries follow lifecycle state

**Status:** CONFIRMED

## Decision

CY Web preserves the Legacy Defect workflow semantics but tightens edit/delete boundaries so completed or actively handled defect cases cannot be silently rewritten or erased.

Canonical lifecycle remains:

```text
created / 已建檔
    ↓
processing / 處理中
    ↓
resolved / 已處理
```

The already-confirmed explicit reopen action remains available:

```text
resolved / 已處理
    ↓ 重新開啟
processing / 處理中
```

Status transitions continue to produce Defect domain history. This is the structured successor to the existing Legacy `logs`; it is not a second duplicate audit mechanism.

## Edit and delete boundaries

### `created / 已建檔`

- ordinary editing is allowed;
- hard delete is allowed only to the record creator or an authorized administrator;
- deletion remains auditable;
- this supports mistaken, duplicate, or test records that have not yet entered actual handling.

### `processing / 處理中`

- ordinary editing is allowed because handling details may still need to be completed or updated while the case is being worked;
- ordinary hard delete is not allowed once the case has entered actual handling;
- if the record itself is later determined to be invalid or wrongly created, it may be explicitly marked invalid rather than physically removed, preserving the record and history.

### `resolved / 已處理`

- ordinary content editing is not allowed;
- ordinary hard delete is not allowed;
- if the same defect case is not actually finished, use the explicit **重新開啟** action to return it to `processing / 處理中`, after which normal editing is available again;
- an independent later defect event or different batch remains a new Defect record rather than a reopen of an unrelated case;
- a wrongly created historical record may be marked invalid rather than erased.

## Authorization

The Legacy hard-coded `admin` check is not the target permission model. The business rule is:

- creator: may delete only while the Defect remains `created`;
- authorized administrator: may also delete only while the Defect remains `created`;
- after the record reaches `processing`, neither role uses ordinary hard delete.

The final implementation should express this through CY Web app permissions rather than permanently binding behavior to the old role string.

## Migration and audit

Legacy Defect records retain their current status and existing `logs` during migration. Where old string logs can be safely interpreted, they may be imported into structured domain history; otherwise the original text must remain available without speculative parsing.

The invalidation action, reopening action, and all status transitions must preserve actor/time and prior history.

## Relation to previous decisions

This decision refines the earlier Defect baseline captured by BD-028. BD-028 established that `resolved -> processing` remains available through an explicit reopen action and that existing Legacy status-history semantics are preserved. BD-033 adds the confirmed edit/delete boundary by lifecycle state.
