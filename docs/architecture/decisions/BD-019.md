# BD-019 — Quantity and unit-price precision baseline

**Status:** CONFIRMED BASELINE

## Decision

For the current CY Web design, business quantities support up to 4 decimal places, and unit prices / costs support up to 4 decimal places.

Formal TWD monetary amounts continue to use the 2-decimal baseline established by BD-018.

```text
quantity scale          up to 4 decimal places
unit price / cost scale up to 4 decimal places
formal TWD amount scale 2 decimal places
```

The higher source precision for quantity and unit price/cost is intentional: calculation inputs may require more precision than the final currency amount, especially for unit conversion, BOM/component quantities, cost calculations and bulk multiplication.

## Calculation boundary

- Quantity and unit price/cost values must retain their approved source precision through intermediate calculations.
- UI formatting must not silently reduce the authoritative stored value.
- Formal monetary rounding occurs according to the document/money rules, not merely because quantity or price is displayed with fewer decimals.
- Exact rounding timing and method remain separately governed and are not implied by this scale decision.

## SMART ERP alignment

This is the current CY Web baseline pending verification of SMART ERP's actual configured quantity, unit-price and cost precision.

If SMART ERP is later confirmed to use different scales or rounding semantics, CY Web should be deliberately adjusted to match the ERP contract before the production D1 schema and financial calculation helpers are frozen.
