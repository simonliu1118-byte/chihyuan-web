# BD-059 — CY Web 人事模組：分三期、超級管理員專用、週年制特休

- **Status:** CONFIRMED (user, 2026-10-19)
- **Scope:** CY Web HR (人事) module
- **Design:** `docs/architecture/HR_MODULE_DESIGN.md`

## Decision

User (2026-10-19): 「增加一個人事模組，要有人事狀態，可以綁定使用者編號（也可以不綁）…後續想擴充成我們自己的人事／假勤／薪資計算功能，但這邊必須要完全符合勞基法規定」.

1. The module is built in three phases: (1) 人事主檔＋特休計算＋薪資異動紀錄, (2) 假勤, (3) 薪資計算. Each phase ships on its own.
2. **Only Super Admin** can see or change any HR data in all three phases. Splitting visibility (人事 vs 薪資, self-service) is decided after phase 3. The module is not part of module grants or 權限群組 until then.
3. 特休 uses the **週年制** (anniversary year from each person's 年資起算日), with the 勞基法第 38 條 table.
4. 身分證字號 is stored (needed for phase 3 勞健保／扣繳), shown masked; revealing the full number is an audited action.
5. Employee self-service (viewing own 特休) is phase 2.
6. Existing records are paper; the user keys them in. No import feature.
7. HR records are never deleted (勞基法第 23、30 條 five-year retention); a person who leaves becomes 離職.
   - **Temporary testing exception (user, 2026-10-20):** until launch, Super Admin can delete an employee and all its HR rows (phase 1 and 2a tables) after typing the 員工編號. The delete is audited without the ID number. It is **removed before launch** (TODO), and test HR data is cleaned up with the rest of the test data.
8. **Editing after the first save (user, 2026-10-20):** HR staff may later edit only the volatile fields (contact, address for mail, store, job title, roster settings, contacts, education, work history, note). Fixed fields (員工編號、姓名、身分證、生日、性別、戶籍地址、到職日、年資起算日) stay with the Super Admin. The split is `HR_VOLATILE_FIELDS` / `HR_FIXED_FIELDS` in `shared/hr.ts`; today only Super Admin uses HR, so it edits everything.
9. **Required fields:** everything except 備註 and 學經歷; 手機或市話至少一個; at least one 緊急聯絡人. Records saved before this rule must be completed before they can be saved again.

## Open items to confirm before the phase that needs them

- Overtime, leave types, 勞健保／勞退 rates and withholding rules (phases 2–3) are listed with their legal source and confirmed by the user or an accountant before release.
