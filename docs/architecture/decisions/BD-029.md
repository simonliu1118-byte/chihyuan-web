# BD-029 — Sales work orders become voidable, not hard-deletable, after ERP issuance

**Status:** CONFIRMED

## Decision

CY Web sales work orders may be hard-deleted only while they remain a purely pre-ERP draft/business work order:

- status is `created / 已建檔`; and
- no SMART ERP sales-order number has been filled.

Once an ERP number has been filled and the work order has entered `issued / 已出單` or any later fulfillment state, ordinary hard delete is prohibited.

## Void semantics

After ERP issuance, the explicit business action is **作廢工單** rather than delete/cancel wording.

Voiding preserves the CY Web work-order identity, ERP number, original line details, prior workflow state and business history. The void event itself must record actor and time through the existing workflow/audit semantics. Whether a void reason is mandatory is left to the later high-risk/correction UX policy.

A voided work order remains searchable and traceable; it must not disappear as if the ERP-linked business event never existed.

## Fulfillment reversal

If the work order has already progressed into picking/shipping or another physical fulfillment state, required reverse/correction operations must be completed before or as part of the void workflow. Voiding must not be implemented as a status-only shortcut that leaves physical-operation side effects inconsistent.

Exact reverse steps for each downstream state will be finalized together with the canonical fulfillment workflow.

## Legacy change

Legacy Desktop currently allows an administrator to hard-delete some ERP-issued work orders before `已出貨`. CY Web intentionally tightens this behavior because ERP issuance creates an external formal-document relationship that must remain traceable.
