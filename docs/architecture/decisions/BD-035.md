# BD-035 — Closed-business customer status is informational and does not block CY Web workflows

**Status:** CONFIRMED

## Decision

CY Web treats `已歇業 / closed_business` as customer status information and presentation, not as an application-level transaction gate.

A customer marked `已歇業` remains visibly identified as such in the Customer list/detail UI, but CY Web does not block normal supported workflows merely because of that status.

## Allowed behavior

The `已歇業` status does not by itself prevent:

- creating or editing Visit records;
- creating CY Web lightweight Quote / customer-item price-history records;
- viewing or maintaining Frequent-item/customer intelligence where otherwise permitted;
- creating a CY Web sales work order from the Customer page;
- selecting the customer in supported work-order/customer lookup flows;
- filling or correcting ERP relationship data on a work order;
- other ordinary CY Web support workflows that are otherwise allowed by their own module rules and permissions.

No special "reopen customer before transacting" step is required by CY Web.

## Product-boundary rationale

CY Web is a complementary/support system. It should not add a second business-eligibility control layer merely because a Customer status says `已歇業`.

If SMART ERP itself later exposes an authoritative restriction on formal ERP transactions, that ERP-owned rule may be reflected by the integration layer after the actual ERP behavior is verified. CY Web must not invent such a restriction in advance.

## UI treatment

The status must remain clearly visible in Customer search/list/detail presentation so users can see that the customer is marked `已歇業`.

Existing visual treatment such as sorting or row styling may be retained, provided it does not disable otherwise permitted actions.

## What this does not change

This decision removes restrictions caused solely by the `已歇業` status. It does not override unrelated controls such as:

- module permissions;
- master-data hard-delete rules;
- Order lifecycle/edit/delete rules;
- ERP fill/correction validation;
- other domain-specific data-integrity constraints.

Whether the lookup value itself is system-protected/configurable is a separate Settings/configuration concern and must not create transaction restrictions.

## Supersession

This decision supersedes the transaction-gating and mandatory reopening portions of BD-014. The historical-retention and visible-status intent remains valid.

Before D1 schema freeze, `BUSINESS_DECISIONS.md`, `CANONICAL_DATA_MODEL.md`, and the Customer workflow audit must be consolidated so they no longer state that `closed_business` blocks new CY Web commercial/support activity.
