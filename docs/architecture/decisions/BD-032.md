# BD-032 — Confirmed outsourcing outbound is corrected through controlled events, not ordinary edit

**Status:** CONFIRMED

## Decision

CY Web distinguishes a planned outsourcing order from an already confirmed physical outbound event.

While an outsourcing order remains `pending_outbound / 待出庫`, ordinary editing may change the contractor, outbound parts/materials, quantities, units, dates, notes and other editable order fields subject to normal validation and permissions.

Once outbound has been confirmed and the order is `outbound / 已出庫`, inventory-affecting outbound facts are no longer ordinary editable form fields.

The following are locked from ordinary editing after confirmed outbound:

- contractor / counterparty relationship;
- outbound part or material identity;
- outbound quantity;
- inventory-relevant unit / conversion facts;
- other fields whose change would alter the confirmed physical stock movement.

Non-inventory descriptive fields may remain editable where doing so does not change the physical or accounting meaning of the outbound event.

## Correcting an outbound record

If goods really were sent out but the recorded outbound facts are wrong, the user uses an explicit **更正出庫** action rather than ordinary edit.

A correction:

- keeps the outsourcing order in `outbound / 已出庫` when the business event is still valid;
- preserves the original outbound event and its history;
- records the corrected facts as a controlled business correction;
- records before/after values, actor and timestamp through structured domain history/audit;
- creates the necessary compensating/delta stock movements so that the stock-movement ledger remains reconcilable;
- does not rewrite or physically delete the original confirmed stock movement.

The exact permission level and whether a correction reason is mandatory will be finalized with the cross-module high-risk/correction UX policy.

## Cancelling an outbound event

If the physical outbound itself is cancelled or reversed, the user uses a separate **取消出庫** / outbound-reversal action.

That action:

- creates the full compensating stock movement required to reverse the confirmed outbound;
- preserves the original outbound event and the reversal event;
- returns the business workflow to a state where the planned order can be corrected and, if appropriate, sent out again.

The exact terminal/intermediate status semantics for all outsourcing cancellation cases remain governed by the broader outsourcing reversal design; this decision establishes that physical reversal is not performed by silently editing the original movement.

## Relation to receiving and later stages

Once receiving has occurred, the original outbound facts are not reopened through ordinary edit. Corrections must follow the appropriate reverse/correction chain for the affected business event.

Existing valid Legacy reverse operations such as cancelling receiving, cancelling pricing and cancelling payment remain useful workflow semantics, but the new implementation represents inventory effects through compensating ledger events rather than destructive balance rewriting.

## Legacy change

Legacy Desktop permits an `已出庫` outsourcing order to remain ordinarily editable until receiving exists and recalculates contractor stock when contractor/part/quantity data changes. That behavior is intentionally not carried forward because confirmed outbound now represents an immutable physical stock event in the canonical movement ledger.
