# BD-039 — Frequent free-text items link to formal Items only through explicit selection

**Status:** CONFIRMED

## Decision

CY Web does not automatically convert or link an unfiled/free-text Customer Frequent entry to a formal Item merely because the text matches an Item name.

A Frequent entry becomes a formal Item relation only when the user explicitly selects the intended Item through the Item lookup / exact formal-item selection flow.

Conceptually:

```text
user explicitly selects formal Item
  -> item_id is stored
  -> current item number/name/spec may be retained as display snapshot where useful

user enters free text only
  -> item_id remains NULL
  -> custom/free-text description is preserved
  -> no automatic same-name or fuzzy reconciliation
```

## Rationale

Legacy Desktop contains compatibility behavior that can take an old string-only Frequent value and match it to `Items` by exact item name. Name equality is not a reliable identity boundary: different formal Items may share similar or identical names, and a historical free-text description may not have meant the current Item master record.

CY Web therefore follows the same explicit-identity principle already used for Order customer binding: the system does not guess an entity relationship from a human-readable name.

## Linking later

If an unfiled Frequent entry later corresponds to a formal SMART ERP Item, the user may explicitly select/link that Item. The operation establishes the stable `item_id` relationship without creating a duplicate Item master.

Where audit/history is retained for Frequent changes, the previous free-text value and the resulting formal Item relationship should remain reconstructable.

## Migration rule

Legacy migration must distinguish records that already carry a trustworthy formal business identifier from name-only/free-text records:

- a Legacy Frequent entry with a formal item number that resolves uniquely and exactly to the imported Item master may be reconciled to `item_id`;
- a string-only/name-only entry must not be auto-linked solely because an Item currently has the same name;
- ambiguous or unresolved entries remain unfiled free-text data rather than being guessed or discarded.

## Relation to previous decisions

- BD-004 keeps the formal Item master ERP-owned.
- BD-011 preserves item aliases/history through controlled remapping rather than identity guessing.
- BD-023 allows Customer Frequent entries to be either a formal Item relation or unfiled free-text customer intelligence.
- The shared Master Lookup implementation may later unify Customer/Item lookup mechanics, but this identity rule applies regardless of UI component design.
