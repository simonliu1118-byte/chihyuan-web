# BD-051 — WorkLog cancel-review requires audit, not retained review-version history

**Status:** CONFIRMED

## Decision

CY Web keeps the Legacy-style controlled WorkLog review reversal:

```text
reviewed / 已審核
  -> cancel review / 取消審核
pending_review / 待審核
```

When an authorized reviewer cancels a completed review, CY Web does **not** need to preserve the cancelled review as a separate historical review version.

The currently effective review/scoring values may be cleared as part of the controlled transition back to `pending_review` so the WorkLog can be reviewed again.

## Required audit evidence

The cancellation itself must create a structured audit/domain-history event containing at least:

- WorkLog identity;
- action = cancel review;
- actor;
- timestamp;
- status transition `reviewed -> pending_review`.

A cancellation reason is not mandatory unless a later UX/audit decision adds that requirement.

The audit event is sufficient evidence that a previous review existed and was explicitly cancelled. The previous individual score values, review remarks, scoring rows, or a full immutable review-version payload are not required to be retained.

## Re-review behavior

After cancellation:

- the WorkLog returns to `pending_review`;
- the prior effective scoring/review values may be cleared;
- an authorized reviewer may perform a new review;
- the new completed review becomes the current finalized review result.

No `review_version`, `cancelled_review_snapshot`, or equivalent version-history table is required for the initial CY Web schema solely for this workflow.

## Relation to BD-012 and BD-041

BD-012 remains valid for an active finalized review: later global scoring-configuration changes must not silently recalculate an already reviewed WorkLog.

BD-051 clarifies the explicit exception: **cancel review is a deliberate controlled reopening action**, not a silent recalculation. Once that action occurs, the previous finalized review may be cleared rather than preserved as a historical score version, provided the cancellation audit event is retained.

BD-041 remains valid: `work_days` is required and review-correctable while review is being performed, with the applicable correction audit requirements.

## Future extension

If the business later needs full historical review-version reconstruction, versioned review snapshots can be added through a forward schema migration. They are intentionally not required for the initial implementation.
