# BD-041 — WorkLog work days are required and review-correctable

**Status:** CONFIRMED

## Decision

`WorkLog.work_days` is a required business field in CY Web and must be greater than zero.

A WorkLog must not be saved with an empty, zero, negative, or otherwise invalid work-day value.

Valid examples include fractional work days such as:

```text
0.5
1
1.5
2.5
```

The exact decimal precision and validation representation will follow the canonical numeric/decimal rules established elsewhere.

## Review behavior

The WorkLog owner enters the work-day value when creating or editing the WorkLog.

During `pending_review / 待審核`, an authorized Admin performing review/scoring may also correct the `work_days` value when necessary to ensure the reviewed average score is calculated from the correct business fact.

An Admin correction to `work_days` during review must:

- validate that the resulting value is greater than zero;
- preserve the previous and new value in structured WorkLog domain history/audit;
- record the reviewing actor and timestamp;
- use the corrected value for the current review/scoring calculation and later historical statistics.

This is a targeted review correction and does not reopen ordinary WorkLog content editing for the reviewer.

## Date range is independent from work days

`date_from` and `date_to` describe the WorkLog's relevant calendar/date interval. They are not a formula for deriving `work_days`.

CY Web must not automatically calculate or overwrite `work_days` from the number of calendar days between `date_from` and `date_to`.

For example, a WorkLog may cover a multi-day calendar interval while representing only a fractional or smaller number of actual work days.

Legacy single-day UI behavior may still set/display the date range conveniently, but the work-day value remains an independently entered business value.

## Scoring implication

Average daily score continues to use:

```text
final reviewed score / work_days
```

Because `work_days > 0` is mandatory, approved historical statistics must not contain the Legacy failure mode where a zero/blank work-day denominator distorts aggregate average scores.

## Relation to existing WorkLog workflow

The existing Desktop-first WorkLog lifecycle remains unchanged:

```text
created / 已建檔
  -> pending_review / 待審核
  -> reviewed / 已審核
```

Owner submit/withdraw and Admin review/cancel-review semantics remain inherited from Legacy Desktop and prior confirmed decisions.

BD-012 remains applicable: finalized reviewed score data is historical and must not be retroactively recalculated from later scoring-configuration changes.
