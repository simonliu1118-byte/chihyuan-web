# BD-058 — 商品單位換算一律直接換成基準單位（單層）

- **Status:** CONFIRMED (user, 2026-10-19)
- **Scope:** CY Web Item unit conversions (`item_unit_conversions`)
- **Refines:** the Item conversion model used by BD-036 (unit conversion semantics unchanged: `1 fromUnit = quantity toUnit`)

## Decision

User (2026-10-19): 「換算一般是一層，一律用基本單位去算，比方說一盒=30包，一箱=180包」.

1. Every conversion row converts **directly to the Item's base unit**: `toUnit` must equal `baseUnit`. Chained rows such as `1 箱 = 6 盒` are no longer accepted on create or update.
2. Each non-base unit appears at most once as `fromUnit`.
3. Display reads `基準單位 包 · 1 盒 = 30 包 · 1 箱 = 180 包`.

## Implementation boundary

- Validation (`worker/item/item-validation.ts`) rejects `toUnit !== baseUnit` with a field error on that row.
- Existing chained rows remain readable: the UI shows each unit converted to the base unit through `unitFactorToBase`, and the next save of that Item writes the single-level form. No data migration is required.
- `unitFactorToBase` and every consumer (BOM, outsourcing, contractor pricing) keep working unchanged; single-level rows are a special case of the existing path resolution.
