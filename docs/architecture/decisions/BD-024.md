# BD-024 — CY Web sales work order is a pre-ERP order that continues through ERP handoff and shipment

**Status:** CORRECTED / CONFIRMED

## Decision

CY Web does have an order-entry workflow. The CY Web record is a **field/pre-ERP sales work order** used by sales staff to capture an order away from the office, after which office staff create the authoritative formal sales order in SMART ERP and return the ERP order number to CY Web.

The CY Web work order then continues through the operational fulfillment/shipping stages until shipment is confirmed.

The earlier interpretation that CY Web was fulfillment-only and should not author any sales-order-like record was incorrect and is superseded by this corrected decision.

## Verified Legacy Desktop workflow

The current Desktop Legacy implementation defines one coherent lifecycle:

```text
CY Web work order created
        ↓
created / 已建檔
        ↓ office creates formal SMART ERP sales order
        ↓ ERP order number is filled back into CY Web
issued / 已出單
        ├──────────────→ picked / 已撿貨
        ↓
waiting_stock / 等到貨
        ↓
picked / 已撿貨
        ↓
shipped / 已出貨
```

Important observed Legacy behavior:

- a newly created work order starts as `已建檔`;
- commercial/work-order contents are editable while the order is `已建檔`;
- the first successful ERP-number fill changes the work-order status to `已出單` automatically;
- fulfillment actions require an ERP number;
- `等到貨` is optional: an `已出單` order may move directly to `已撿貨`;
- `已出貨` may only be reached from `已撿貨`;
- Legacy Desktop supports cancelling shipment by moving `已出貨` back to `已撿貨`;
- the ERP number is a linked external SMART ERP reference, not the CY Web work-order identity.

These observed transitions validate the candidate stable workflow codes already identified in the canonical draft:

```text
created
issued
waiting_stock
picked
shipped
```

## System-of-record boundary

CY Web owns:

- the pre-ERP sales work order created by field sales;
- customer/item/quantity/unit/price/note and instruction data needed for office staff to create the ERP order;
- CY Web work-order identity and history;
- the handoff state before/after ERP entry;
- waiting-stock, picking and shipment operational workflow.

SMART ERP owns:

- the authoritative formal sales-order document;
- the official ERP order number/document identity;
- ERP posting/accounting/inventory effects;
- formal ERP corrections/cancellation according to ERP rules.

CY Web must never treat its own work-order ID as the SMART ERP formal order number.

## ERP handoff

Legacy `erpNo` has a defined semantic role: it is filled after office staff create the formal sales order in SMART ERP.

Conceptually:

```text
salesperson creates CY Web work order
        ↓
office staff receive work order
        ↓
office staff create formal SMART ERP sales order
        ↓
ERP order number filled back into CY Web
        ↓
CY Web fulfillment / picking / shipping workflow continues
```

The UI wording `ERP 單號 — 打單後回填` and the Legacy transition on first ERP-number fill confirm this intent.

## Editing / correction boundary

The current Desktop Legacy implementation only enables ordinary work-order editing while the status is `已建檔`. Once the order has reached ERP handoff / later fulfillment states, the commercial work-order fields are no longer ordinarily editable.

This is a strong baseline because it prevents CY Web from silently diverging from an ERP order that office staff have already entered.

Exact future permissions for exceptional correction, ERP-number correction, cancellation and deletion should be reviewed separately before final implementation rather than copied mechanically from Legacy role checks.

## Mobile divergence

Legacy Mobile contains older order-flow remnants such as `待處理` / `修改後待處理` and an older `orderNo` path, while the newer Desktop implementation uses the verified five-state lifecycle above.

CY Web must not preserve Desktop and Mobile as two different business contracts. The new Web application should use one canonical order lifecycle and adapt only its presentation for Desktop/Tablet/Mobile.

## Migration implication

Legacy `Orders` is a first-class business source containing both pre-ERP commercial work-order data and downstream fulfillment state. It must not be treated as merely a cache/projection of SMART ERP orders.

Migration should preserve:

- CY Web work-order identity/history;
- customer relationship;
- item lines and appropriate historical snapshots;
- notes/instructions/flags;
- workflow state;
- linked `erpNo` where present;
- last-update/history information needed for continuity and audit.

## Relation to customer-item quotes

This does not change BD-020 through BD-022. CY Web customer-item quote history remains a lightweight customer/item price-reference function and is separate from both the CY Web sales work order and SMART ERP formal quotation documents.
