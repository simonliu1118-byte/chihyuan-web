# BD-024 — SMART ERP owns sales-order CRUD; CY Web supports fulfillment/shipping workflow only

**Status:** CONFIRMED

## Decision

Formal sales orders belong to SMART ERP. CY Web is not a sales-order authoring system and must not provide ordinary create, edit or delete operations for the authoritative sales-order document.

CY Web's role in the sales-order domain is the operational fulfillment/shipping layer around ERP-owned orders.

## System-of-record boundary

SMART ERP owns at least:

- creation of the formal sales order;
- sales-order number and authoritative document identity;
- customer/item/quantity/price and other ERP-owned commercial order fields;
- edits/corrections to the formal sales order;
- cancellation/deletion/voiding according to ERP rules.

CY Web must not create a competing sales-order number or maintain an independently editable duplicate commercial order document.

## CY Web fulfillment scope

CY Web may read/import/synchronize the ERP sales order and maintain Web/mobile operational state needed to execute shipment, for example:

- order visibility/search for fulfillment staff;
- waiting-for-stock / availability follow-up;
- picking workflow;
- shipment preparation;
- shipped/completed operational status;
- fulfillment notes, timestamps and responsible employees;
- other warehouse/shipping support explicitly approved later.

The final canonical model should distinguish ERP-owned sales-order facts from CY Web-owned fulfillment state rather than treating all current Legacy `Orders` columns as one writable order entity.

## Architectural implication

The draft `orders` model and its current Legacy-derived status workflow must be reclassified during canonical-model consolidation.

Conceptually, the target should be closer to:

```text
ERP sales order projection/reference
  +
CY Web fulfillment/shipping state
```

rather than:

```text
CY Web editable sales order
```

Where an ERP order field is synchronized into CY Web, it should normally be read-only and reconciled from SMART ERP. CY Web-specific fulfillment fields remain writable only within CY Web's operational scope.

The exact synchronization source/mechanics remain dependent on the future SMART ERP Bridge and interim migration/import design.

## Legacy migration implication

Legacy `Orders` contains both commercial-order data and fulfillment/workflow data. Migration must classify those fields by ownership instead of copying the whole row into a writable CY Web order table.

Historical Legacy order information may be retained for continuity and migration traceability, but future formal sales-order CRUD belongs to SMART ERP.

## Relation to customer-item quotes

This boundary does not affect BD-020 through BD-022. CY Web customer-item quote history remains a lightweight customer/price-reference feature, not a formal ERP sales-order or quotation-document authoring workflow.
