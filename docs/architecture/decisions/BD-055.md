# BD-055 — Legacy UX is reference evidence, not a replication target

- **Status:** CONFIRMED
- **Scope:** CY Web feature/UI implementation

## Decision

The Legacy GAS system is a behavior and usability reference, not a screen-by-screen replication target.

CY Web must be designed and implemented using the new Web architecture, shared reusable components, RWD + Adaptive presentation, modern interaction patterns, and the current confirmed business model.

At the same time, proven Legacy behavior should not be discarded merely because it came from GAS. If an existing interaction, workflow detail, information layout, keyboard behavior, or usability convention is still useful under the new architecture, it may be retained or adapted.

The required implementation test is therefore:

1. identify the underlying user/business need;
2. determine whether the Legacy behavior still serves that need well;
3. keep or adapt the useful behavior where appropriate;
4. redesign GAS-era workarounds, duplicated implementations, obsolete visual constraints, or interactions that no longer fit the new Web system;
5. implement repeated mechanics through shared CY Web foundations rather than duplicating them per page/module.

## Examples

Suitable to retain/adapt when useful:

- clear create/view/edit/save/cancel workflows;
- keyboard-first data-entry behavior;
- useful in-page related-record context;
- Customer/Item lookup semantics;
- status visibility and business-action affordances;
- proven field grouping or workflow ordering.

Not to copy automatically:

- GAS refresh/update prompts;
- duplicated Desktop/Mobile application trees;
- page-specific copies of common UI/logic;
- direct DOM/global-state patterns;
- Legacy CSS/layout constraints;
- blocking alert boxes for routine events;
- visual structures that existed only because of GAS/Sheets limitations.

## Implementation rule

Legacy should be treated as **evidence to evaluate**, not as either:

- a mandatory blueprint to reproduce; or
- something to discard wholesale.

New CY Web implementation is allowed to preserve good Legacy UX, but the resulting code and interface must conform to the new architecture and shared-component model.
