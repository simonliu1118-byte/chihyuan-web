# BD-052 — Initial CY Web field set follows validated Legacy/GAS design; SMART ERP field ownership is deferred

**Status:** CONFIRMED

## Decision

Direct SMART ERP data integration is a longer-term project and is **not a prerequisite** for the initial CY Web data model, Final Data Dictionary, D1 schema, or first production implementation.

For the initial CY Web implementation, Customer, Item and related business fields are based primarily on the already-audited Legacy GAS/Desktop design and confirmed CY Web Business Decisions.

The project should therefore complete the current schema using the business fields already required by the existing CY workflow instead of blocking on a future SMART ERP database/View investigation.

## Initial field-design rule

Legacy/GAS is used as the **business-field reference**, not as a physical database schema to copy literally.

Therefore CY Web should:

- retain useful Legacy business fields and workflows that remain applicable;
- normalize repeated/JSON-shaped values into relational child tables where appropriate;
- use immutable internal IDs and proper foreign keys instead of mutable names/business numbers;
- apply confirmed snapshot, audit, workflow and precision decisions;
- remove migration-only or obsolete Legacy structures;
- avoid inventing speculative SMART ERP fields that are not currently needed by CY Web.

## SMART ERP boundary for the initial version

Existing Business Decisions still apply conceptually:

- SMART ERP remains the primary ERP;
- ERP customer/item numbers remain separate from CY Web internal identity;
- CY Web must not duplicate official ERP numbering authority;
- formal Item/customer-number relationships may later be synchronized through the approved ERP Bridge direction.

However, the exact classification of every Customer/Item field as `ERP-owned`, `CY Web extension`, `read-only`, or `synchronized` is **deferred** until the future SMART ERP integration project investigates the actual available schema/View/API behavior.

This deferred ownership classification does not block the initial D1 schema.

## Future integration behavior

When SMART ERP integration is implemented later:

1. inspect the actual approved SMART ERP read interface;
2. map available ERP fields to the existing CY Web canonical fields;
3. determine authoritative ownership and sync direction field by field;
4. change editable/read-only behavior through forward migrations/configuration as required;
5. preserve CY Web internal IDs and historical document snapshots;
6. do not destructively redesign unrelated CY Web extension data merely because ERP integration is added.

## Relation to BD-002 through BD-004

This decision does not cancel the long-term SMART ERP architecture in BD-002 through BD-004.

It clarifies **implementation timing**: the initial CY Web field set can be finalized from the validated Legacy/GAS business model now, while exact SMART ERP field ownership remains a later integration concern.
