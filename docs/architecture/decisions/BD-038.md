# BD-038 — Contractor Price has one current record per Contractor + Item

**Status:** CONFIRMED

## Decision

For a given Contractor and Item, CY Web allows only one current Contractor Price at a time.

The current price record contains the pricing unit and unit price defined by BD-036:

```text
Contractor + Item
  -> pricing unit
  -> unit price
```

A change from one pricing unit and/or price to another is an update to the current Contractor Price, not a second simultaneously active price for the same Contractor + Item.

## Rationale

Legacy pricing lookup effectively finds a price by Item and can therefore become ambiguous if duplicate price rows for the same Contractor + Item exist. CY Web must not depend on list order or silently choose one of several simultaneously active prices.

The initial model intentionally avoids introducing a more complex price-rule engine, priority rules, quantity-tier pricing, or multiple concurrent pricing modes unless a real business need is confirmed later.

## Price history

Updating the current Contractor Price must preserve structured history sufficient to identify:

- Contractor;
- Item;
- previous pricing unit;
- previous unit price;
- new pricing unit;
- new unit price;
- actor;
- timestamp.

Historical price changes are audit/history facts and are not additional current-price rows.

## Completed outsourcing pricing remains immutable by later master-price changes

When an Outsourcing record is priced, its pricing snapshot preserves the pricing facts actually used for that transaction, including at minimum:

- Item identity/snapshot as required by the transaction model;
- pricing unit;
- applied unit price;
- quantity used for pricing after any required unit conversion;
- subtotal.

Later changes to the Contractor Price must not rewrite already-priced historical Outsourcing records.

## Future extension

If future operations require multiple concurrent prices for the same Contractor + Item (for example quantity tiers, date-effective contracts, or separate pricing modes), that requirement must be modeled explicitly as a price-rule structure. Duplicate current rows must not be used as an implicit substitute.

## Relation to previous decisions

- BD-006 defines transaction snapshot behavior.
- BD-017 through BD-019 define decimal and monetary precision.
- BD-030 defines referenced master-data retention.
- BD-036 defines Contractor Price as Item + explicit pricing unit + unit price and requires canonical unit conversion before calculation.

## Data-model implication

The D1 model should enforce one current Contractor Price per Contractor + Item at the service/database boundary, while retaining price-change history separately from the current record.
