# BD-057 — CY Web 權限群組 presets system and module access for its members

- **Status:** CONFIRMED (user, 2026-10-18)
- **Scope:** CY Web Module Access administration
- **Refines:** BD-037 (direct `app_member_module_access` remains the runtime authority)

## Decision

An Identity Admin or Super Admin may define **權限群組**: a named set of other CY systems (系統使用權, e.g. 志遠記帳 Web, 電子發票工具) and CY Web modules (業務模組 and ERP 查詢).

1. A person belongs to **at most one** group.
2. A group member uses **exactly** the group's systems and modules and cannot be changed individually; changes are made on the group and apply to every member at once.
3. Groups manage **both** 系統使用權 and CY Web modules (user, 2026-10-18: simpler than splitting them). CY Web itself (the core application) is always available and is not part of a group.
4. When a person leaves a group, or the group is deleted, the person's current systems and modules are **kept as personal settings**.
5. Super Admin is not placed in groups (automatic full access); an admin cannot change their own group.

## Implementation boundary

- Storage: `module_access_groups`, `module_access_group_modules`, `module_access_group_applications`, `app_member_module_groups` (migration 0015).
- Runtime authority is unchanged: joining a group and every group change materialize the members' rows in `app_member_module_access` in the same D1 batch, so `requireModuleAccess` / `checkModuleAccess` read only direct grants. Group tables are administration state, not a second authority.
- System access is owned by CYID, so it cannot share the D1 batch: after the D1 write the Worker sets each member's CYID application access to exactly the group's set (registered, enabled, non-core systems), changing only cells that differ. Members CYID did not update are returned as `applicationSyncFailed`; the UI also shows any member whose CYID access differs from the group (a failed sync or a change outside CY Web) and offers 重新套用 (`POST /groups/:id/sync`).
- The individual module API and CY Web's system-access proxy refuse group members with `MODULE_ACCESS_GROUP_MANAGED` (the proxy says so only to an access admin; others get CYID's answer).
- Group edits use optimistic `revision`; group create/update/delete and membership changes are structured audit events (BD-053/054).
- Legacy `app_tags` remain non-authoritative; groups are not a revival of tags.
