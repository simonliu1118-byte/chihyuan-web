# BD-057 — CY Web 權限群組 presets CY Web module access for its members

- **Status:** CONFIRMED (user, 2026-10-18)
- **Scope:** CY Web Module Access administration
- **Refines:** BD-037 (direct `app_member_module_access` remains the runtime authority)

## Decision

An Identity Admin or Super Admin may define **權限群組**: a named set of CY Web modules (業務模組 and ERP 查詢).

1. A person belongs to **at most one** group.
2. A group member uses **exactly** the group's modules and their module access cannot be changed individually; changes are made on the group and apply to every member at once.
3. Groups manage **CY Web modules only**. Access to other CY systems (系統使用權) stays per person.
4. When a person leaves a group, or the group is deleted, the person's current modules are **kept as personal settings**.
5. Super Admin is not placed in groups (automatic full access); an admin cannot change their own group.

## Implementation boundary

- Storage: `module_access_groups`, `module_access_group_modules`, `app_member_module_groups` (migration 0015).
- Runtime authority is unchanged: joining a group and every group change materialize the members' rows in `app_member_module_access` in the same D1 batch, so `requireModuleAccess` / `checkModuleAccess` read only direct grants. Group tables are administration state, not a second authority.
- The individual grant API refuses group members with `MODULE_ACCESS_GROUP_MANAGED`.
- Group edits use optimistic `revision`; group create/update/delete and membership changes are structured audit events (BD-053/054).
- Legacy `app_tags` remain non-authoritative; groups are not a revival of tags.
