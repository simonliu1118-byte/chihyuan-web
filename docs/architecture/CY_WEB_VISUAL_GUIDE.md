# 0. 規範強度

- **`CORE`** — 所有志遠 Web App 共同遵守；要例外須寫進該專案 `PROJECT_RULES.md`。
- **`RECOMMENDED RANGE`** — 建議範圍，不是像素鎖定。
- **`APP CHOICE`** — 依畫面語意選擇；選最簡單可用的那一種。
- **`REFERENCE`** — CY Web 已驗證的實作，可直接沿用，但不強制其他專案使用同一程式碼。
- **`DEFERRED`** — 刻意延後，尚不作為驗收條件。

| 範圍 | 強度 | 方向 |
|---|---|---|

# 1. 定位 — `CORE`

志遠 Web App 是給公司同仁每天做事的工具，不是行銷網站或數據看板。目標：

- 看起來屬於同一個志遠產品家族，但不模仿 Windows 視窗外觀（`PROJECT_RULES.md` §5）。
- 桌面版重視資訊密度、快速查詢與鍵盤效率；手機版重視查詢、確認與觸控。
- 每一個畫面都要回答「現在是什麼狀態、下一步要按哪裡」。

關鍵字：

- **Business Web** — 平實、可長時間使用；不用大面積漸層、陰影或彩色卡片。
- **Text-first** — 文字標籤為主，圖示為輔；按鈕寫出結果（「建立客戶」「儲存修改」），不用「確定」「OK」。
- **One way** — 同一件事只有一種呈現方式（一個轉圈、一套狀態色、一種選擇器），不讓每個模組各做一套。

不採用的做法（使用者 2026-10-18 審查 GPT 預覽後確認）：

- 小於 12px 的字、整頁 10–11px 的密排；
- 沒有功能的入口（匯出、匯入、通知鈴、「⋯」更多選單）；
- 示意用、沒有真實資料的統計卡或趨勢圖；
- 頁碼分頁（改用搜尋＋「載入更多」）；
- 把動作藏在每列的選單裡；
- 登入頁大面積裝飾標語、頂端列重複放使用者資訊。

# 2. 字型與字級 — `CORE`

## 2.1 字型

```
"Noto Sans TC", "PingFang TC", "Microsoft JhengHei", system-ui, sans-serif
```

數字、單號、品號、統編使用等寬字（`--cy-font-mono`，或 `.cy-mono`），方便對齊與比對。

## 2.2 字級角色

| Token | 大小 | 用途 |
|---|---|---|
| `--cy-fs-xs` | 12px | 最小字級：狀態標籤、表格附註、說明小字。**不得再小** |
| `--cy-fs-sm` | 13px | 次要文字：欄位標籤、清單第二行、筆數 |
| `--cy-fs-md` | 14px | 內文、按鈕、表格內容 |
| `--cy-fs-input` | 14px（觸控 16px） | 輸入框；觸控裝置 16px 避免 iOS 自動放大 |
| `--cy-fs-lg` | 16px | 區塊標題 |
| `--cy-fs-xl` | 18px | 明細標題 |
| `--cy-fs-2xl` | 20px | 頁面標題（頂端列） |

字重：一般 400；標籤、目前頁籤、區塊標題 500–600；粗體只用在標題與重要金額，不整頁加粗。

# 3. 顏色與主題 — `CORE`

## 3.1 主題切換

- 預設跟隨系統；使用者可選「系統／淺色／深色」，記在 cookie（`cyweb-ui-theme`），不使用 localStorage。
- 實作：`:root` 定義淺色，`@media (prefers-color-scheme: dark)` 搭配 `:root:not([data-cy-theme="light"])`，另以 `:root[data-cy-theme="dark"]` 強制深色。
- 頁面第一次繪製前套用主題，不得閃爍（`applyStoredTheme`）。

## 3.2 中性色與主色

| 角色 | 淺色（霧白） | 深色（石墨） |
|---|---|---|
| 背景 `--cy-bg` | `#F6F6F9` | `#17171F` |
| 面板 `--cy-surface` | `#FFFFFF` | `#23232F` |
| 次面板 `--cy-surface-muted` | `#F8F8FB` | `#2A2A37` |
| 凹陷 `--cy-surface-sunken` | `#F1F1F6` | `#1D1D27` |
| 分隔線 `--cy-border` | `#E3E3EC` | `#383848` |
| 輸入框線 `--cy-border-input` | `#8E91A6` | `#75738C` |
| 文字 `--cy-text` | `#282A3A` | `#EFEDF8` |
| 次要文字 `--cy-text-muted` | `#676B7E` | `#B6B4CB` |
| **主色 `--cy-accent`（商務藍）** | **`#3D63D2`** | **`#9DBBFF`** |
| 主色淡底 `--cy-accent-soft` | `#EAF0FC` | `#2A3550` |
| 主色上的文字 `--cy-on-accent` | `#FFFFFF` | `#172446` |

主色只用在：主要按鈕、目前位置（側欄、頁籤、選取列）、連結、焦點框。不用主色做大面積背景。

## 3.3 狀態顏色語意 — `CORE`

所有流程狀態只用這五種語氣，定義集中在一處（CY Web：`src/runtime/modules/status-flow.ts`）：

| 語氣 | 顏色 | 意思 | 例子 |
|---|---|---|---|
| `warning` | 黃 | **等這裡的人處理** | 瑕疵已建檔、工單待 ERP、委外待出庫、日誌待審核 |
| `info` | 藍 | 進行中，等外部或下一階段 | 處理中、已開單、已出庫 |
| `success` | 綠 | 完成 | 已處理、已出貨、已付款、已審核、使用中 |
| `danger` | 紅 | 作廢、錯誤、失敗 | 已作廢、連線中斷 |
| `neutral` | 灰 | 草稿、停用、未知 | 日誌已建檔（草稿）、已停用 |

- 同一顏色在每個模組代表同一件事；新增狀態時先決定它屬於哪一種語氣。
- 顏色永遠搭配文字，不可只靠顏色表達狀態。
- 訊息框同樣使用語氣：成功綠、錯誤紅、提醒黃、說明藍；不得用黃色警告框顯示成功。

# 4. 版面與間距 — `CORE / RECOMMENDED RANGE`

## 4.1 外框（App Shell）

- **側欄**（`--cy-sidebar-w` 216px）：品牌、依群組排列的模組（業務模組／系統管理／工具）。
- **頂端列**（`--cy-topbar-h` 56px）：左側為標題＋一行 30 字內說明＋頁面工具（管理員專屬設定按鈕等）；手機不顯示說明。右側為外觀切換與個人選單；選單打開後只有「我的帳號（密碼、Email）」「登出」。不再使用 ⓘ 說明圖示或說明視窗。
- **頁面主要動作不放頂端列**（使用者 2026-10-18：電腦上右上角太遠）：「＋ 新增…」放在清單工具列最左邊、搜尋框前面；沒有清單工具列的頁面（備份、設定）放在內容最上方的 `.cy-page-toolbar`，主要動作在最左邊。
- **內容區**：左右留白 `--cy-gutter`（桌面 20px、觸控 14px）。
- 手機（≤ 820px）：側欄收成抽屜；頂端列保留標題、外觀切換（單一圖示按鈕）與頭像。

## 4.2 左清單、右明細 — `CORE`（清單型模組）

- 寬螢幕同時顯示清單（280–340px）與明細；清單固定在畫面內捲動。
- 清單上方是工具列：第一列是「＋ 新增…」與搜尋框（`.cy-md-toolbar-lead`），接著是篩選、狀態按鈕列、筆數（「共 N 筆」或「已載入 N 筆，還有更多」）。
- 手機一次只顯示一邊：點清單進明細，明細頂端有「‹ 返回清單」。
- 明細未選擇時顯示空狀態：一句話說明下一步（「從左側清單選一位客戶，或按清單上方的『＋ 新增客戶』」）。

## 4.3 間距

建議使用 4 的倍數：4／8／12／16／20／24px。面板內距 12–16px，區塊間距 16px，欄位間距 12×16px。

## 4.4 圓角與陰影

| Token | 值 | 用途 |
|---|---|---|
| `--cy-radius-sm` | 6px | 分段按鈕內的選項、小元件 |
| `--cy-radius-md` | 8px | 按鈕、輸入框、訊息框 |
| `--cy-radius-lg` | 10px | 面板、對話框、卡片 |
| 全圓 | 999px | 狀態標籤、狀態篩選按鈕 |

陰影只用兩種：`--cy-shadow-sm`（分段選項、浮起的小元件）與 `--cy-shadow-lg`（對話框、下拉選單）。面板以邊框區隔，不靠陰影。

# 5. 元件 — `CORE`

所有元件都使用共用樣式與共用元件；模組 CSS 只做版面，不重新定義按鈕、輸入框、頁籤等共用元件。

## 5.1 按鈕

| 種類 | Class | 用途 |
|---|---|---|
| 主要 | `.cy-op-button.primary` | 每個區塊最多一個；寫出結果（「建立工單」「確認出貨」） |
| 一般 | `.cy-op-button` | 次要動作（「修改」「取消」） |
| 危險 | `.cy-op-button.danger`／`.danger-solid` | 刪除、作廢；`danger-solid` 只用在確認視窗 |
| 安靜 | `.cy-op-button.quiet` | 列內的小動作（「移除」「修改」） |
| 小型 | `.compact` | 表格列、區塊標題列 |

- 高度 `--cy-control-h`（32px／觸控 44px），小型 `--cy-control-h-sm`（28px／40px）。
- 流程按鈕放在明細標題列右側，依狀態只顯示可以按的那幾顆。
- **忙碌**：按鈕保留原文字，以 `aria-busy` 在文字前顯示轉圈，同時停用。不要把文字換成「儲存中…」。流程按鈕只讓被按的那一顆轉圈（`usePendingAction`），其餘停用。

## 5.2 輸入框、下拉、日期

- 一律使用 `.cy-op-input`（textarea、select、date 亦同），焦點時主色框線＋3px 淡色光暈。
- 欄位標籤在上方（13px 次要色），必填加紅色 `*`。
- 停用：凹陷底色、次要文字；唯讀：次面板底色。
- 表單在寬螢幕兩欄、手機一欄；長欄位（地址、備註）跨整列。
- 紀錄修改表單（清單右側明細）：「取消」「儲存」放在表單標題列右側，也就是原本「修改」按鈕的位置，標題列捲動時固定在畫面上方（`.cy-edit-header`），不另在底部放一組（使用者 2026-10-18）。彈出視窗維持底部動作列。
- 各模組的設定由標題列上的「設定」按鈕開啟大視窗（只對管理員與超級管理員顯示，權限依 BD-043）；不使用模組內設定頁籤，也不做共用的「系統管理／設定」入口：客戶（客戶分類、客戶狀態、負責部門）、商品（商品分類）、工作日誌（日誌類別、日誌平台、計分設定）。

## 5.3 邊打邊選（EntityPicker）

選客戶、商品、協力廠商等**大量資料**時，一律用邊打邊選（`EntityPicker`），不用長下拉或另放「篩選選單」輸入框。下拉內搜尋中顯示小轉圈；沒有結果時說明「找不到符合的…」。選項少（狀態、類型、單位）才用一般下拉。

## 5.4 頁籤與分段按鈕

- **頁籤**（`.cy-op-tabs`）：切換同一筆資料或同一模組的不同區域（拜訪紀錄／報價紀錄；代工單／BOM）。目前頁籤主色字＋底線。
- **分段按鈕**（`.cy-segmented`）：在 2–4 個互斥的「方式」中選一個（查詢方式：品號／品名；外觀：系統／淺色／深色）。以 `aria-pressed` 標示目前選項；側欄等窄處用 `.compact`。

## 5.5 狀態標籤與狀態點

- 狀態一律用 `StatusChip`（全圓、12px、淡底＋同色字），清單與明細同一套。
- 不是狀態標籤的控制項需要表示狀態時（例如「已連線」按鈕），用 `.cy-status-dot` 小圓點加文字。

## 5.6 狀態篩選按鈕列 — `CORE`

清單的狀態篩選用 `StatusFilter`，取代「全部狀態」下拉：

- 「全部 N」＋各狀態按鈕，每顆有狀態色點與筆數；按一下篩選，再按一次或按「全部」取消。
- 筆數由後端第一頁一起回傳（`statusCounts`），條件與清單相同、只排除狀態篩選；不在前端自行加總已載入的列。

## 5.7 下一步提示

明細標題下方一行藍底提示（`NextStep`）：寫出目前狀態在等什麼、要按哪顆按鈕（「料件交給協力廠商後按『確認出庫』」）。完成狀態改為灰底說明，作廢沿用作廢提示。

## 5.8 訊息框、提醒與 Toast

- 頁面結果訊息用 `FeedbackBanner`：成功綠、錯誤紅。
- 錯誤同時以提醒視窗告知（`useFeedback`），避免使用者錯過。
- 一般說明用 `.cy-notice-info`，需要注意用 `.cy-notice-warning`（例如「結果只顯示最新 2,000 筆」）。

## 5.9 對話框

- 共用 `Dialog`：標題、可選說明、內容、底部動作列（取消在左、主要動作在右）。
- 簡短輸入用 `useFormPrompt`，確認用 `useConfirmation`；不得使用瀏覽器 `alert／confirm／prompt`。
- 危險確認的按鈕寫出後果（「放棄修改」「作廢工單」）。

# 6. 清單與表格 — `CORE / APP CHOICE`

- **清單列**（`.cy-op-list-row`）：第一行粗體主名稱、第二行次要資訊（單號 · 日期），右側狀態標籤。選取列主色淡底＋左側 3px 主色條。
- **表格**（`.cy-op-table`）：表頭中性色、數字靠右（`.num`）、等寬數字；寬表格在容器內橫向捲動，頁面本身不得橫向捲動。
- **筆數與分頁**：顯示「共 N 筆」；超過一頁時列尾「載入更多」，不用頁碼。
- **空狀態**：一句話說明為什麼是空的、可以做什麼。
- 手機上的表格改為卡片（每筆一張，欄位兩欄排列），資料語意不變。

# 7. 載入、忙碌與空狀態 — `CORE`

| 情境 | 呈現 |
|---|---|
| 切換模組、確認權限、首次進入模組 | 只顯示 `Loading`（轉圈＋「載入中…」）；清單第一頁讀完才整頁一起出現 |
| 點清單讀取明細 | 整個明細區顯示 `Loading`，不在舊資料上方顯示「更新…中」文字 |
| 清單重新查詢 | 筆數處顯示小轉圈（`Loading inline`），清單保留 |
| 按鈕處理中 | 按鈕文字前轉圈（`aria-busy`） |
| 長時間背景工作（ERP 查詢） | 轉圈＋說明要等多久（「可能需要一到數分鐘」） |

全站只有一個轉圈樣式（`.cy-loading-spinner`）；尊重 `prefers-reduced-motion`。

# 8. 鍵盤與表單流程 — `CORE`

- 紀錄表單：Enter 依序跳到下一個欄位，最後停在儲存按鈕；再按 Enter 才儲存（`enterAdvancesFields`）。
- 簡短視窗（原因、密碼、驗證碼）：最後一欄按 Enter 直接送出（`enterAdvancesThenSubmits`）。
- Ctrl／⌘＋Enter：任何欄位直接儲存。textarea 內 Enter 照常換行；下拉展開時 Enter 由下拉處理。
- 查詢表單（ERP、稽核）：Enter 直接查詢。
- 存檔缺欄位時指出是哪一欄、第幾列；不可按了沒反應。
- 有未存檔修改時，切換清單、頁籤或模組要先詢問；沒有修改不詢問。

# 9. 響應式 — `CORE`

# 10. 無障礙 — `CORE`

- 文字與背景對比達 WCAG AA（主色按鈕白字 5.4:1、深色主題按鈕字 8.0:1）。
- 所有可操作元件有可見焦點（主色框線＋光暈）。
- 狀態不只靠顏色：標籤有文字，篩選按鈕有文字與筆數。
- 只有圖示的按鈕要有 `aria-label`；分段按鈕用 `aria-pressed`、頁籤用 `role="tab"`／`aria-selected`。
- 載入用 `role="status"`、錯誤用 `role="alert"`。

# 11. 文字與用語 — `CORE`

- 介面一律正體中文；必要的拼音使用威妥瑪拼音。
- 按鈕寫動作結果；提示寫下一步；錯誤寫原因與怎麼做。
- 使用者看得懂的業務用語（「ERP 客戶編號」），不顯示技術代碼或資料庫 ID。
- 日期時間一律台灣時區（`formatDateTime`、`taipeiToday`），不依瀏覽器語系。

# 12. 圖示 — `CORE`

# 13. 實作規則 — `CORE`

- 單一樣式來源：`src/app.css`（tokens、外框、共用元件）＋`src/ui/forms.css`（表單）。模組 CSS 只能使用 tokens，不得自訂顏色值、字級、按鈕或輸入框樣式。
- 不使用 `!important`；需要提高優先序時用正確的選擇器。
- 共用元件：`Loading`、`StatusChip`、`StatusFilter`、`NextStep`、`FeedbackBanner`、`Dialog`、`useConfirmation`、`useFormPrompt`、`EntityPicker`、`useMasterDetailPane`／`MasterDetailBack`／`MasterDetailEmpty`、`useLoadMore`／`LoadMoreRow`、`AccountMenu`、`usePendingAction`、`enterAdvancesFields`。
- 新模組先延伸共用元件；真的需要新的共用樣式，加在共用層並更新本文件，不在模組內做第二套。
- 不得在瀏覽器保存業務資料；外觀偏好以 cookie 保存。
