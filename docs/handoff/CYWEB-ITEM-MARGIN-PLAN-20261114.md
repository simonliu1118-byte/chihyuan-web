## 3. 核對發現與設計落點

1. 原始 shared 稅別只有 none／inclusive／exclusive 且可空；舊 none 在不同 UI 處標為「未指定／無稅別」。不能直接解讀為新的不計稅。計畫提議新增明確 no_tax 碼、舊 none／NULL 待補，沿用明確含稅／外加稅碼。
2. items 的歷史 CHECK 不接受新碼；計畫要求新的 forward migration 及舊備份相容，不修改歷史 migration 或強制給所有舊商品預設。
3. 新建／修改必填與既有待補可讀需要分開，包含停用／啟用等使用 profile update 的入口；不另建繞過驗證的路徑。
4. 第一階段僅非網路通路，連各平台基本毛利也放第二階段；既有商品網路售價的編輯不因此消失。
5. 計算使用單一 Worker 核心及現有精確單位換算，顯示前才舍入，不複製成本／售價或前端公式。
6. 商品／瑕疵原頂層分頁保留，新增的是商品詳情內商品資料／毛利分析，不建立新主模組。
7. 第二階段保留全部活動／費率／AI 需求，補上訂單情境邊界、折讓不重扣、區間依利率選極值及未知條件標示；費率 AI 只能提案，人工核准才生效。
8. 發布與遷移尚未執行。計畫把整表重建的 N 列成本、待補 U 列成本、額度／分批與回退相容性寫入未來發布準備，不假裝已有正式列數或備份證據。
