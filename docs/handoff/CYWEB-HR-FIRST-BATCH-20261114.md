## 問題與處理

1. 正式09:00–10:00時段假，10:00打卡仍被算遲到60分鐘：月明細與門市異常各批次取得有效假單，交同一出勤核心。已銷假不排除，銷假後重新計遲到。
2. 員工／月份／門市／年度快速切換，舊請求可能覆蓋新結果：共用useLatestRequest用查詢身分及遞增序號排除過期成功、錯誤、finally；卸載及A→B→A也會失效。主要人事清單／詳情、證號顯示、排班及提醒、出勤／員工分頁、請假總表／詳情均套用；年度假日選項使用effect生命週期防護。
3. 人事桌機與手機頁籤直接setTab，繞過編輯保護：改由同一NavigationGuard統一詢問、取消切換保留草稿、處理中拒絕切換。共用guard只增加可選本地文案，既有模組預設不變。排班人員／格子、補休／特休、假單視窗也註冊保護，不複製第二套權限或導航系統。
4. 給予補休／調整特休失敗仍關視窗：變更函式回報成敗，成功才關閉；失敗保留內容並在視窗顯示錯誤。同步ref鎖防連點，處理中鎖欄位／關閉／導航。已成功寫入後的重讀失敗不當成未寫入而重送。
5. 出勤7小時35分被半小時格式舍入：實際工時改「7小時35分鐘」，分鐘資料原樣；加班與請假仍維持原半小時單位。
6. 出勤選單只讀前100人：加入既有cursor「載入更多員工」，保留已選員工，直到nextCursor為空；不是一次無界拉全員。測試可選第105人。

## 出勤計算邊界

- 有效假單需cancelled_at IS NULL，依員工＋日期分組，不把不同員工假單互套。
- 時段假與班別休息區間取聯集後，從「排班開始到首筆完整打卡／最後完整打卡到排班結束」排除；聯集避免重疊重複扣除，超過班別部分不計入。
- 只剩未覆蓋的應出勤分鐘才列遲到／早退。整天有效假或時段假完整覆蓋所有工作區間，沒有打卡亦不列曠職；僅部分覆蓋而整天無打卡仍保留曠職。缺卡不自動補正。
- 實際打卡工時仍由打卡扣休息計算，請假不會增加打卡工時；居家無打卡沿用自動正常工時，有有效時段假時扣掉相應覆蓋。擺攤與不排班兼職的原豁免不變。
- 沒有班別起訖的純分鐘假不猜應出勤區間，不擴充夜班／跨日、扣薪或月薪計算。
- 每個月明細及整店異常各增加一個JSON1 IN有效假單查詢，上限10000筆，超出明確報錯，不截斷當完整；沒有逐日／逐員工查假單。原門市100人界限保留，選人分頁不擴大單店異常查詢上限。

## 介面與操作邊界

- 出勤儲存直接安裝PUT已回傳的attendance、清草稿，不額外GET；寫入失敗保留現有草稿，處理中欄位禁止編輯，避免新輸入被成功回應清掉。
- 切換選人／月份前先確認草稿，確認後清掉舊畫面；請求不吻合時不安裝。人事主檔選人時清除舊詳情，證號回應也核對當前人員／頁籤。
- 正式假單送出有同步鎖；附件階段鎖住員工、日期、假別等正式內容，避免畫面修改後仍把附件掛舊假單。已建立時只重試附件、可略過附件完成，未新增第二張假單。尚未上傳任何附件時可替換失敗檔；部分已上傳則維持原清單以保留進度。
- 這些是操作保護，沒有增加每月薪資按鈕、試算流程或改既有請假額度規則。第二批表格／手機版整理與第三批薪資規則仍未實作。
