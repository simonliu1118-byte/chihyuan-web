- 電池條算法：「假設第一次去 100，那 100 個就是 100%，剩下 10 個就是 10%；這時候我們又發料 100 過去，總數變成 110 個，那 110 個就是 100%；又用到剩 5 個的時候就是 5/110=5%（四捨五入到整數）」

## 2. 已定案事項（執行者不得更改）

### 2.1 新流程

```
建立代工單（多種成品＋預計數量＋BOM）
  ↓ 發料（可多次）────────→ 料件進「廠商庫存」（＋）
  ↓ 交貨入庫（可多批，每批有 ERP 單號）→ 依 BOM 從廠商庫存扣料（−）
  ↓ 每種成品都交齊 → 自動「已交齊」；交不足可手動「結案」
對帳付款（與代工單分開；依廠商結帳方式：月結／單次）
```

代工單狀態只有四個，**由系統依資料決定**，不再有計價／付款狀態：

| 狀態 | 條件 |
|---|---|
| 待發料 | 還沒有任何發料 |
| 生產中 | 已發料，還有成品沒交齊 |
| 已交齊 | 每種成品已交 ≥ 預計 |
| 已結案 | 使用者手動結案（要填原因）；可「重新開啟」回到依資料判斷的狀態 |

- 交貨可以超過預計數量（以實際為準），進度最多顯示 100%。
- 刪除代工單：只有「沒有發料也沒有交貨」才能刪。

### 2.2 代工單內容

- 表頭：協力廠商、工單日期、備註；系統帶出單號（沿用 `outsourcing_ref` 格式）與廠商結帳方式。
- **成品表**（多列）：成品、BOM、預計數量、單位、已交（唯讀）、進度條。BOM 下拉只列該成品啟用中的 BOM；只有一個時自動帶入；可留空（沒有 BOM 的成品交貨時不扣料）。
- **發料紀錄**：每次發料一筆（日期、備註、多列料件：料件、數量、單位）。**發料視窗**預設帶出建議量 = 未交量 × BOM 用量 − 廠商現有庫存（小於 0 視為 0），使用者可改、可加 BOM 以外的料件。
- **交貨入庫**：每批一筆（入庫日期、**ERP 單號**、備註、多列成品：成品、BOM、本次數量、單位、單價）。**交貨視窗**列出本單每種成品與未交量，本次數量預設空白；下方即時預告「會從廠商庫存扣：○○ −1,600 片…」。
- 單價：交貨時帶入當下的協力廠商單價（快照）；沒有設定單價就留空，到對帳時再填。
- 發料、交貨都可以「取消」（產生反向異動、留下紀錄），條件：該筆交貨還沒進入**已確認**的對帳單。取消發料可能讓廠商庫存變負數，允許，畫面用紅字顯示。
- 所有新增／修改／取消都寫共用 Audit。

### 2.3 廠商庫存（ledger）

- 仍以 `contractor_stock_movements` 為唯一依據，現有量 = 該廠商＋料件的異動加總。異動種類：`issue`（發料 ＋）、`consumption`（交貨依 BOM 扣 −）、`return`（退料 −）、`adjust`（盤點調整 ±）、各自的反向沖銷。
- **退料**：廠商把料退回公司；從代工庫存頁發動（日期、數量、備註），可一次退多種料件。
- **盤點調整**：輸入「實際數量」或「增減量」擇一，原因必選：損耗、盤點差異、其他（其他要填說明）。
- 退料、盤點調整**只能用在該廠商曾經發過料的料件**。

### 2.4 電池條（使用者定義，不得改算法）

- **基準量** = 該廠商＋料件「最近一次發料後」的現有量（含當次發料）。每次發料都重設基準；退料、盤點調整、交貨扣料、取消交貨都**不**重設基準。取消發料時，基準回到前一次有效發料後的量。
- **百分比** = 現有 ÷ 基準，四捨五入到整數；超過 100% 顯示 100%。
- 顏色：≥ 50% 綠、20%～49% 黃、< 20% 紅。現有 < 0：整條紅、百分比顯示「—」、數量紅字粗體。
- 例：發 100 → 100%；用到剩 10 → 10%；再發 100（現有 110）→ 110 為 100%；用到剩 5 → 5%；再發 100（現有 105）→ 105 為 100%。

### 2.5 代工庫存頁

- 每個協力廠商一個可收合區塊（標題：名稱、結帳方式、料件數）。預設只列有庫存（現有 ≠ 0）的廠商與料件，可切換顯示全部；搜尋廠商、料件。
- 區塊內依**成品**分組（用該廠商未結案代工單的成品 BOM 對應料件；不屬於任何成品的放「其他料件」）。組標題顯示「現有料件還能做約 N ○」= 各料件 floor(現有 ÷ 每單位成品用量) 的最小值；有料件 ≤ 0 時改顯示「料件不足，需補料」。
- 每列：品號、料件、電池條＋百分比、現有、基準（補料後）、動作（`退料`、`盤點調整`，`cy-op-button mini soft`）。
- 右上「異動紀錄」：開視窗列出異動（日期、廠商、料件、種類、數量、現有、原因／來源單號、操作人），可篩選廠商。

### 2.6 對帳付款（新頁籤）

- 協力廠商主檔新增**結帳方式**：月結／單次（預設單次）。
- **對帳單**一張屬於一個廠商：
  - 建立時選廠商；月結廠商預設「選月份」→ 自動帶入該月交貨日期內所有尚未對帳的交貨明細；單次廠商預設「勾選交貨批次」。兩種方式都可用，結帳方式只決定預設。
  - 明細列：日期、代工單、ERP 單號、成品、數量、單位、單價、金額。草稿時單價可修改（格子即輸入）。
  - 「＋ 其他費用／折讓」：說明＋金額（可負），例如運費、瑕疵扣款。
  - 金額：明細金額 = 數量換算到計價單位 × 單價，保留到小數 2 位；**合計四捨五入到元**。不再因有小數而拒絕。
  - 狀態：草稿 → 已確認（所有明細都有單價才能確認；確認後鎖定）→ 部分付款／已付清（依付款加總自動判斷）。已確認且沒有付款可「取消確認」回草稿；草稿可刪除（明細回到未對帳）。
- **付款**：付款日、方式（現金／匯款／支票／其他）、金額、備註；可分多次；可刪除單筆付款（留 Audit）。
- 代工單的交貨表顯示每批的對帳狀態（待對帳／對帳中／已確認／已付清）。

### 2.7 版面（設計稿，使用者 2026-11-10 確認）

- 頁籤順序：**代工單｜對帳付款｜代工庫存｜協力廠商／單價｜BOM**（手機用頂部頁籤 `ModuleSections`）。
- ① 代工單：左清單（廠商、單號、日期、狀態）；右邊單據頂部按鈕「＋ 發料」「＋ 交貨入庫」（primary）「結案」(soft)、⋯（刪除、重新開啟）；下面三張表：成品（含進度條）、發料紀錄、交貨入庫（含對帳狀態）。
- ② 交貨入庫視窗（`large`）：上方 `EntryTable` 兩格（入庫日期、ERP 單號），下方成品表格內直接輸入，扣料預告在表格下方。
- ③ 代工庫存：見 2.5。
- ④ 對帳付款：左清單（廠商、期間或日期、金額、狀態）；右邊對帳單（表頭、明細表、其他費用／折讓列、合計列），下方付款表。
- 所有輸入都是表格式（格子就是輸入區），不准一欄一欄往下排；單位一律下拉；BOM 顯示 `recipe_ref` 名稱，**不得顯示 `BOM #id` 這類系統編號**。

## 5. 實作指引

- 數量沿用 scaled4、金額沿用 money2 與既有單位換算（`allowedUnits`、canonical conversion）；異動一律換算成料件基準單位存入 ledger。
- 電池條的基準量從 ledger 推算（最近一筆有效 `issue` 之後的累計），不另存可變欄位；做成共用小元件（例如 `src/ui/data/StockGauge.tsx`），寫進 `UI_COMPONENT_CATALOG.md`。
