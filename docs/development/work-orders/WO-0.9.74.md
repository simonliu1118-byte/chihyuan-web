- 分支：cyweb/wo-0.9.74-receipts-dates　PR：#（執行者填）

## 1. 背景（使用者原話，2026-11-03）

- 「這邊幫我改一下，到貨記錄介面太差，以及到貨紀錄應該要可以修改，以免填錯不能改」
- 「全部的日期選擇器元件我想都改成現在門市訂購自己做的這個日期元件」

同一則訊息的「已經到貨或部分到齊就不應該還能被修改」已由 Claude 在 V0.9.73 處理：已有到貨或結掉品項的叫貨單不再顯示「修改」，`revise` 回 409。本單不要動這部分。

## 2. 已定案事項

### A. 到貨紀錄的畫面

目前叫貨單明細上方的「到貨紀錄」只有「ERP 進貨單號／到貨日期」兩欄，看不出每次到了哪些品項、各多少，也沒有操作。改為：

- 每筆到貨紀錄一列，依到貨日期新到舊。每列包含：
  - 到貨日期；
  - ERP 進貨單號（等寬字）；
  - 本次到貨品項摘要，例如「測試膠帶 10 捲、測試標籤 100 張」；品項多時換行，不截斷；
  - 登記人與登記時間（目前 API 回傳的 `createdBy` 是空字串，要補上人名，作法同修訂紀錄的 `by`）；
  - 右側操作：「修改」「刪除」，用 `IconButton`＋`Icons.edit`／`Icons.remove`（`variant="table"`）。
- 手機（≤680px）改為卡片，每個欄位帶 `data-label`，比照售後維修清單。
- 區塊標題沿用現有「到貨紀錄 N 筆」。表格沿用共用表格樣式，不另做一套。

### B. 修改到貨紀錄

- 按「修改」開啟與「登記到貨」**同一個對話框**，帶入原本的進貨單號、到貨日期與各品項數量。不要另寫一個對話框。
- 可以改：ERP 進貨單號、到貨日期、每個品項的到貨數量。
  - 數量可以改成 0，代表這筆到貨沒有這個品項；全部改成 0 不允許（請用刪除）。
  - 可以補上原本沒勾的品項。
  - 每個品項的上限是「叫貨數量 − 其他到貨紀錄已到的數量」。
  - 已結掉的品項：可以減少，不能增加。
- 驗證與「登記到貨」相同（11 碼進貨單號、日期、數量）。「同一張叫貨單已有相同進貨單號」的提醒，修改時要排除這筆自己。
- 儲存成功後，叫貨單版本＋1，修訂紀錄寫一筆，例如「修改到貨 341A-20261023001：測試膠帶 10 → 8、日期 10/23 → 10/24」。

### C. 刪除到貨紀錄

- 用 `useConfirmation`，說明「刪除後這些品項的已到數量會扣回」，確認鍵為危險色。
- 刪除後版本＋1，修訂紀錄寫一筆「刪除到貨 ○○○」。
- 刪掉最後一筆到貨、而且沒有結掉的品項時，叫貨單會回到「已送出」狀態，這時「修改」按鈕會再出現。這是預期行為，不要另外擋。

### D. 全站日期欄位改用共用 `DateInput`

- 目前還有約 40 個原生 `<input type="date">`，分布在 18 個檔案：
  - 客戶（含報價單）、商品、瑕疵、銷售工單、委外／代工、工作日誌、人事（含假單、設定）、異動紀錄；
  - ERP 客戶、供應商、交易紀錄對話框；
  - 叫貨頁（4 個）。
  
  請以 `grep -rn 'type="date"' src` 為準，全部換成 `src/ui/forms/DateInput.tsx`。
- 密度：
  - 表單裡的欄位（`Field` 包著的）用 `density="regular"`；
  - 清單上方的篩選列、表格內用預設的 `compact`。
  
  換完後每個畫面都要看過，「YYYY/MM/DD」不可被截斷（WO-0.9.71 進貨輔助抽屜就發生過）。
- `min`／`max`／`required`／`disabled` 照原本的值帶過去。`onChange` 的參數從 event 改成 ISO 字串，注意原本有用 `e.target.value` 的地方。
- 起訖日區間（例如叫貨清單的 起～迄）保持兩個 `DateInput` 並排，中間的「～」不變。
- `erp-item-query.css` 裡針對 `input[type=date]` 的樣式，換完後若沒有用到就刪掉。
- 加一條 source 檢查（放在現有 `validate:source` 或 `form-keyboard.test.mjs`）：`src` 下不得再出現 `type="date"`，避免之後又有人用原生日期欄位。

## 3. 範圍

- **API**（`worker/http/ordering-routes.ts`）：
  - `PUT /api/business/ordering/orders/:id/receipts/:receiptId`
    - body `{expectedVersion, erpPurchaseNo, receivedDate, lines:[{lineId, quantity}]}`；
    - 在同一個 D1 batch 裡更新主檔、刪除再插入明細；版本守門沿用 `mutate`。
  - `DELETE /api/business/ordering/orders/:id/receipts/:receiptId`
    - body `{expectedVersion}`；
    - 在同一個 batch 裡刪除明細與主檔。
  - 兩者都只允許 `storedStatus` 為 SENT 的叫貨單（作廢的不行）。
- **前端**：
  - `OrderingPage.tsx`：到貨紀錄區塊；登記到貨對話框加上「修改模式」（帶入原值、標題改為「修改到貨」、儲存呼叫 PUT）。
  - 日期欄位替換涉及上面列的檔案。
- **測試**：
  - route：修改數量、日期、單號；數量超過上限 422；全部為 0 時 422；刪除後已到數量扣回；作廢單 409；版本衝突。
  - page：到貨紀錄列顯示品項摘要；按修改帶入原值；刪除會先確認。
  - source 檢查：不得有 `type="date"`。

## 4. 不做

- 不改「登記到貨」本身的流程與欄位。
- 不改人事的 `type="month"`（年月欄位），`DateInput` 不處理月份。
- 不新增 migration。到貨明細的已到數量本來就是由 `ordering_receipt_lines` 加總而來，修改或刪除明細後自動正確。
- 固定一條：不加多餘的測試與防護（共通規則 §11.4，使用者 2026-10-29）。只做本單要求的功能與實際會發生的錯誤處理；不加重複驗證、不會發生的情境測試。

## 5. 實作指引

- 一律使用共用元件，不要寫 `<svg>`：
  - `Dialog`／`useConfirmation`；
  - `IconButton`＋`Icons`；
  - `Field`、`DateInput`；
  - `FeedbackBanner`。
- 修改模式的對話框和登記到貨共用同一個 state 與 form，用一個 `receiptId?: number` 區分。
- 摘要文字的組字（品名＋數量＋單位）抽成一個小函式，列表和修訂紀錄共用。
- 版本 V0.9.76（V0.9.74、V0.9.75 已由 Claude 用掉；若中間又有其他版本先合併則接續）。
