## 1. 既定畫面與來源

商品詳情及毛利同一畫面，瑕疵維持獨立功能。成本、成本稅別、各平台售價、單位與分類全取商品主檔，不在毛利區重填或覆寫；商品與派生毛利共用同一資料owner及後端權威快照。

毛利是自動閱讀結果，沒有試算按鈕、件數輸入、模擬訂單、搭購或保存試算收據。平台費率與優惠共用設定建議放既有商品模組設定按鈕，非主要功能頁籤；此入口及共用管理角色仍待確認。

只有ITEMS而無ITEMS_COST_MARGIN：成本與稅別位置留白，整個毛利區不掛載、不取規則；後端API亦不提供成本／毛利。

## 2. 每個平台的表格：先列費率與兩層毛利

以蝦皮為使用者舉例，欄位順序如下；其他平台同一結構：

| 項目 | 顯示內容 |
| --- | --- |
| 平台基本費率 | 各基本費目a＋b＋c……，保留每項名稱、計費基礎與金額／比例 |
| 扣除基本費率毛利 | 主檔售價扣除全部基本費用後的單件毛利額／率 |
| 平台活動費率 | 目前適用的平台活動費項，逐項列出 |
| 扣除基本＋活動費率毛利 | 主檔售價扣除基本及活動費用後的單件毛利額／率 |
| 滿件折扣 | 列出該平台有效滿件方案，例如滿2件9.9折、滿3件9.8折、滿5件9.7折 |
| 優惠券 | 列出全部對該平台／商品適用的有效券：名稱、滿額門檻、折抵／上限及負擔條件 |

基本費率與活動費率是兩類平台收費，不可與滿件折扣／優惠券混成同一類。費用設定需明確標示基本／活動分類；一項費用不重複計入兩類。費目計費基礎或固定／比例不同時保留逐項算式，不把不同基礎的百分比直接相加。

**不再另列「扣除優惠券後毛利」這個獨立結果項目。優惠券的作用反映在下方各滿件檔的區間。**

缺費率資料標待設定／待確認；明確沒有參加活動與不知道活動費率是不同狀態，不能把未知費用當0。上方兩個毛利結果各保留可展開費用明細。

## 3. 滿件折扣各一列，全部優惠券形成區間

若有效滿件方案有三檔，畫面就是三列：

| 滿件條件 | 折數 | 計入全部適用優惠券後的毛利區間 | 操作 |
| --- | --- | --- | --- |
| 滿2件 | 9.9折 | 所有合法券結果的最低～最高毛利率，端點附單件毛利額 | 查看明細 |
| 滿3件 | 9.8折 | 此折數下獨立計算全部券結果，再取最低～最高 | 查看明細 |
| 滿5件 | 9.7折 | 此折數下獨立計算全部券結果，再取最低～最高 | 查看明細 |

折數是使用者舉例，實作依設定動態產生；9.9／9.8／9.7折分別為0.99／0.98／0.97，不是三折數相乘。各列在滿件折數下計入平台基本＋適用活動費用，再將全部適用優惠券逐一計算／納入合法組合。

「全部優惠券計算進區間」表示每一張適用有效券都要納入候選，不是只挑一張代表券，也不是把所有券金額直接累加扣除。券互斥時分別計算，可併用時才計入該合法組合；滿件與券能否並用亦依設定。

區間每端點顯示來自哪張券／哪個合法組合、門檻、折抵、賣家負擔與每件分攤明細。畫面不提供使用者選券或選情境來啟動計算。只有一個有效結果就顯示單一數值；缺必要規則時標待確認，不硬湊範圍。

### 3.1 不自行套用固定訂購件數

滿件門檻用來識別該折扣檔，**不是已決定整張訂單固定只買2／3／5件**。刪除上一提案「各檔直接以門檻件數計算」及「單品1件預設」；不能用這些未確認假設先裁掉其他優惠券。

每張滿額券仍保留自己的滿額條件、門檻基準、賣家負擔、封頂及分攤方法。由規則明定如何換算成該商品的折抵／負擔後，才可與每個滿件折數組合，不能忽略門檻或假設未知搭購。實作前若現有券設定不足以決定單件分攤，必須列出缺項待確認，不自行引入互動試算或任意訂購量解決。

這裡待釐清的是資料規則的分攤基準，不是要求使用者在閱讀毛利時輸入件數。結果不宣稱為任意真實訂單的保證獲利。

## 4. 唯一後端計算核心與資料流

1. 從同一商品aggregate取得主檔成本／稅別、售價、單位與分類，引用revision。
2. 有界讀取適用且有效的基本費率、活動費率、滿件折扣與全部優惠券版本，一次取得後在記憶體重用。
3. 先產生上方扣基本費用、扣基本＋活動費用的兩個毛利結果。
4. 每個滿件折數各自計算所有適用券／合法組合；依費率的實際基礎、門檻、上下限、出資、取整及分攤算各結果，並取毛利率極值。
5. 賣家折讓反映於實際收入，不在費用再扣一次；平台出資不當成賣家成本，稅務條件未知時不得冒用扣抵假設。
6. 費用後貢獻額＝實際未稅商品收入－對應淨成本－賣家負擔費用淨額；比率以實際未稅收入為分母，全部以一致單件單位呈現。
7. 沿用精確有理數與既有單位換算，按平台規則取整及最後顯示舍入；零收入比率為—，負值保留並警示。

畫面可使用「毛利」方便閱讀，資料型別仍區分商品基本毛利與費用後貢獻額／率。費用本身各按確認的稅別及扣抵條件處理，不一律除1.05。

預設結果隨商品詳情同次回應。只有商品／規則版本變更時按需重取共用結果，不為每列或每券重查商品／D1，也不另建前端公式、商品選取或輪詢owner。無成本權限時不回派生結果。大量規則／組合需有界計算，未完成不得冒稱完整極值。

## 5. 本版設定範圍

目前優惠只有滿件折扣、滿額折價（以優惠券形式列示）；不擴充其他活動、搭購或試算系統。沿用既有平台id與網路價格，新增必要的規則／版本／提案，不建立第二份商品價格或試算收據主檔。

| 類別 | 必要設定 |
| --- | --- |
| 基本／活動費率 | 類別、費目、固定／比例、計費基礎、上下限、稅務／取整、平台／商品範圍、期間、來源、審查狀態／版本 |
| 滿件折扣 | 門檻件數、折數、範圍、期間、與券是否併用、啟停／版本 |
| 滿額折價／優惠券 | 券名、滿額門檻、折抵／封頂、門檻基準、出資／賣家負擔、單件分攤基準、互斥／可併、範圍、期間、啟停／版本 |
| 變更提案／歷史 | 前後規則版本、來源、影響比較、提案者／審查者、結論與理由，不覆寫已生效歷史 |

規則重疊需在儲存時解決，不能默默按最後修改選一筆。時間採台北時區，讀取時依有效期間判斷；不逐活動新增排程。資料表與migration編號待實作依當時最新schema決定。

管理入口建議在商品模組設定按鈕，內分基本／活動費率、滿件折扣、優惠券、提案／歷史。毛利區只閱讀與展開明細；設定以共用RecordRows／Dialog＋EntryTable，閱讀表沿用cy-op-table cy-rt與820px手機樣式。

## 6. 權限與AI核准

沿用ITEMS＋ITEMS_COST_MARGIN作閱讀門檻；共用規則與人工費率核准建議先限SUPER_ADMIN，仍待使用者確認，沒有自動授權。

優惠規則完整且使用者明確授權時，AI可經受控API套用；平台費率必須附官方來源送審，人工核准後才生效。內部影響比較沿用同一自動計算列，不新增互動試算。

AI專用委派身分須核對受支援CYID契約與最小scope，不挪用小編token、不信任AI自報人員、不給D1憑證。寫入帶revision／重複請求識別、原子更新及Audit，記來源、操作者、前後規則與生效時間；泛用Audit不寫成本／毛利正文。

## 7. 執行與驗收

| 批次 | 工作 |
| --- | --- |
| 2A | 確認費率分類、券折抵分攤資料，建立版本／提案及備份／權限 |
| 2B | 基本費用、基本＋活動費用兩層毛利；各滿件檔×全部有效券的自動區間 |
| 2C | 商品詳情同頁表格、設定入口與明細、1440／390目視驗收 |
| 2D | 受控AI變更、費率人工審核、Audit／衝突／撤權與完整回歸 |

必要驗收：基本與活動費不重複、不同費基不錯加、所有券均納入候選、三滿件檔分列不連乘、券互斥／可併、滿額門檻／封頂、賣家出資／分攤、同單位毛利、零／負值、活動失效、缺資料、權限及主檔不被改寫。沒有試算UI或手動件數／搭購，也不能寫死2／3／5件的訂單假設。

文件確認後才開始實作；每批handoff列實際讀寫量、驗證與Claude待審欄。大量商品的規則影響比較另做明確啟動的有界分批工作，不在每次開啟商品時全站重算。正式操作仍另待具體授權。
