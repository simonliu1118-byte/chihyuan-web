## 1. 畫面與資料來源

商品詳情與毛利同一畫面：上方原商品資料，下方唯讀通路毛利與網路平台毛利。瑕疵保留獨立功能。平台費率及優惠共用設定建議放既有商品模組設定按鈕，入口仍待確認。

成本、成本稅別、平台售價、單位與分類全取主檔；不能在毛利區另填或覆寫。平台費用、滿件折扣、滿額折價由有權限者在共用設定管理，商品只套用符合其平台／分類／商品範圍且有效的規則。

只有ITEMS而無ITEMS_COST_MARGIN：成本及稅別位置留白、毛利整區不掛載、不請求規則；API不回成本或毛利。權限管理先維持上一提案：具成本權限者閱讀、平台共用設定與核准建議先限SUPER_ADMIN，尚待使用者確認，沒有自動授權。

## 2. 網路平台顯示項目

每個有主檔網路價的平台自動列出下列各列；滿件檔位從有效設定動態產生，不寫死2／3／5件：

| 項目 | 顯示方式 |
| --- | --- |
| 扣除平台費用後的毛利 | 原主檔售價扣費用的單件毛利額／率，作比較基準 |
| 扣除優惠券後的毛利 | 依本版滿額折價規則，顯示可適用優惠後的單件毛利區間；無滿額折價可用時維持單一數值 |
| 滿2件9.9折 | 此滿件折數扣平台費用，再納入合法滿額折價，列單件毛利區間 |
| 滿3件9.8折 | 獨立一列，不能與其他滿件檔折數相乘 |
| 滿5件9.7折 | 獨立一列，依同一規則計算區間 |

以上折數為使用者舉例，不是預設活動。9.9折＝99%、9.8折＝98%、9.7折＝97%；有哪個檔位就顯示哪個檔位，沒有滿件活動就不出現這些列。

每列保留毛利額、毛利率、區間端點與「計算明細」。明細列出原價、滿件折扣後價格、平台費用、可用滿額折價與每件分攤，閱讀即可；沒有「試算」「計算」或「套用情境」操作。

畫面可沿用「毛利」稱呼，但計算／資料型別分開基本商品毛利與費用後貢獻額／率，避免財務語意混淆。

## 3. 區間的來源與自動計算基準

區間來自滿額折價規則，而不是任意挑數量或搭購組合。各滿件折數分列，不把9.9／9.8／9.7折壓成一個不明範圍。

### 3.1 件數／訂單基準建議（需確認）

為了不用使用者輸入件數、仍能明確判斷滿額門檻與每單折抵的每件分攤，建議：

- 基準列及「扣除優惠券」列以該商品1件為基準。
- 每個滿件列使用它的門檻件數，例如滿2件用2件、滿3件用3件、滿5件用5件。
- 以同商品、同平台的這一組件數計算金額；不假設訂單還有其他商品，不模擬未知搭購。
- 畫面明細註明「以X件計算、折抵分攤回單件」。這是提案的自動基準，不能冒稱使用者已確認，也不能宣稱同折數的任意購買件數都得到完全相同區間。
- 若使用者想讓「滿5件」涵蓋所有5件以上數量，需再確認自動採用的數量範圍與每單折抵分攤方法，不能拿某個固定門檻結果冒充全部數量。

### 3.2 取區間端點

在每列固定基準下，自動判斷有效且合法的滿額折價組合，計算各組合後取最低／最高單件毛利率，端點各帶對應毛利額：

- 判斷門檻採活動設定的折前／折後金額，不自行猜測。
- 每檔滿件折扣先判定，不能把滿2、滿3、滿5的折數連乘。
- 滿件與滿額能否併用，依已設定規則；不可併用時不把兩者同扣。
- 可選券未使用的合法結果可作上界；強制折讓不得當成可不扣，依活動設定判斷。
- 滿額折價的上限與賣家負擔照規則處理，不把平台出資當賣家成本。
- 沒達門檻、缺必要條件或活動已到期者不納入；只有一種有效結果就顯示單一數值，不硬湊區間。
- 費率或滿額折價資料不足時顯示待設定／待確認，不能把未知費用當0或捏造區間。
- 不同端點可能來自不同券，明細說明適用條件；不是所有真實訂單的保證獲利。

## 4. 計算核心

沿用唯一Worker計算核心及第一階段主檔淨成本／單位換算：

1. 一次讀取權威商品aggregate，供商品資料與毛利區共用，不另外建立選取商品或載入owner。
2. 按平台、日期及商品範圍有界讀取當次有效費率／兩類優惠版本，一次取得後在記憶體重用，不為每個檔位或組合重查D1。
3. 對基準列／每個滿件檔位取得固定基準件數，依滿件折數得到各自商品收入。
4. 依滿額折價門檻、互斥／併用、取整及分攤計算合法結果；賣家折讓先反映收入，不能在費用再扣一次。
5. 平台費用依各費目計費基礎、上下限、稅務與取整規則計算，不假設所有費用一律除1.05。
6. 貢獻額＝實際未稅商品收入－該件數淨成本－賣家負擔費用淨額；貢獻利率＝貢獻額／實際未稅商品收入。金額以對應件數分攤回單件供比較。
7. 精確分數至平台要求的取整點及最後顯示才舍入，零收入比率為—，負毛利保留並警示。

預設毛利隨商品詳情同次回應；商品或費用規則更新時按需重新取得兩區共用資料，不做背景輪詢或因切換顯示而重載商品。後端始終檢查目前權限、商品revision與規則版本，不能把前端回傳成本當權威。

純合成驗算：淨成本100、含稅售價210、固定淨費用10時，扣費用後毛利率45%。若合法滿額券由賣家折21，收入未稅180、貢獻70、比率38.89%；若用券／不用券均合法，範圍38.89%～45%。這不是實際平台費率；門檻及每件分攤必須依該列基準，不能套到其他件數冒稱同一區間。

## 5. 共用設定

沿用既有item_web_platforms／item_online_prices與商品分類；平台名稱、售價、成本沒有第二份主檔。本版僅新增必要規則／版本／提案，不新增模擬訂單或保存試算收據資料表。

| 設定 | 必要內容 |
| --- | --- |
| 平台費用 | 費目、固定／比例、計費基礎、上下限、取整、稅別及扣抵條件、適用範圍、期間、官方來源、查證日期、審查狀態／版本 |
| 滿件折扣 | 檔位門檻件數、折數、適用平台／分類／商品、期間、與滿額折價是否併用、啟停／版本 |
| 滿額折價（優惠券） | 滿額門檻、折抵金額／上限、門檻基準、平台與賣家負擔、互斥／可疊、適用範圍、期間、啟停／版本 |
| 提案與歷史 | 新舊規則、來源、生效範圍、影響比較、提案者／審查者、結果與理由，不覆寫已生效歷史版本 |

其他百分比券、任選商品組合、搭購、任意手動折扣與互動試算不列本版活動範圍。原有費率／優惠管理的必要物流等賣家費用可作費目，但不另外擴充活動種類。

同費目覆寫順序建議商品＞分類＞平台；同層重疊設定必須先解決衝突，不能默默按最後修改挑一筆。日期以台北時區處理，查詢當下判斷失效，無需逐活動另建排程。

設定使用既有表格式元件與Dialog；毛利區只做閱讀及明細。每筆規則標明全平台／分類／商品作用範圍，避免誤以為只改目前商品。

## 6. AI、權限與審核

既定核准差異不變：使用者明確授權且內容完整的滿件／滿額優惠可由AI經API套用；平台費率需附官方來源送審，人工核准才生效。這些是規則管理接口，不是給使用者額外操作的毛利試算功能。

API提供讀規則、提交優惠變更、規則影響比較、授權套用、提費率提案、人工核准及歷史；內部均使用同一自動計算核心。影響比較讀出修改前後的自動毛利列，不新增人工填售價／數量／搭購的試算入口。

沿用CYID／ITEMS_COST_MARGIN的既有權限來源及最小scope。AI專用委派身分須先核對CYID受支援契約，不能自報人員、挪用小編token或取得D1憑證。寫入帶revision與重複請求識別；原子更新規則與Audit，保留來源、操作者及前後版本。Audit不存可被其他人讀取的商品成本／毛利明細。

規則／組合計算有界；過多時顯示計算未完成或待確認，不截斷後冒稱完整區間。查詢依平台／狀態／期間索引，不在每個商品開啟時全站重算；費率提案的完整影響比較若需大量商品，另做使用者啟動的分批作業並先估列數與額度。
