## 畫面與資料來源

商品詳情及毛利同一畫面，瑕疵維持獨立功能。成本、成本稅別、售價及單位只讀商品主檔。商品詳情 GET 同次回應包含 Worker 計算的 margin；前端使用同一份商品快照，不為毛利另查一次商品、不自行重算公式。

閱讀區沒有試算按鈕、訂購件數輸入、搭購或訂單組成設定。平台費率及優惠在既有「商品設定」的「平台費用與優惠」管理，不新增主要功能頁籤。設定使用 RecordRows、EntryFields、CheckField 與既有 Dialog／未儲存保護；結果使用 cy-op-table、cy-rt、ExpandToggle、StatusChip 及共用 820px RWD。

## 設定欄位

| 區塊 | 欄位 |
| --- | --- |
| 基本費率 | 費用名稱、計算方式（百分比／固定金額）與數值、最低／最高收費 |
| 蝦皮品類費率／Mo+品類費率 | 兩平台獨立品類名稱、方式／數值、最低／最高收費；商品只套用所選一個品類，加入基本費率 |
| 活動費率 | 同上 |
| 賣家負擔運費 | 勾選；勾選後填貨運別、金額 |
| 滿件折扣 | 滿件數、折數 |
| 優惠券／滿額折價 | 活動／優惠券名稱、折數或金額、滿額門檻、折抵上限 |

設定依平台共用，不建立第二份商品成本或售價。不增加適用範圍、生效期間、啟停、出資比例、AI 提案／核准、平台來源等表單欄位。基本與活動費率各至少一筆；確定零費用明確填0。最低不得高於最高。滿件數至少2且不重複，折數介於0至10（9.9折＝0.99），滿額門檻為正整數元。

設定中明文顯示：**優惠券一律不可並用；每張券都與滿件折扣一起計算。** 9折、滿600、上限20完全合法，在600元時實際折20，不因原折扣60大於上限而拒絕。

## 區間與計算約定

1. 每張券使用自己的門檻 T，找下一個不同的門檻 U。區間比較 T 與 U−1 元，例如600折20、下一門檻800，就比較600折20與799折20。這是本功能的門檻區間約定，不代表平台強制客人於800元更換券。
2. 不計算真實訂單如何湊滿。單件折抵＝滿件折扣後商品含稅價 × 該端點整單實際折抵／該端點整單金額。沒有滿件折扣的300元商品，600折20分攤10元；799折20約分攤7.51元。
3. 百分比券於兩端重新算折數及上限；固定券亦套用上限，折抵最多等於整單金額。相同門檻的券各自計算，下一界取下一個不同門檻。
4. 最後門檻沒有下一界：固定／有上限券折讓占比趨零，最高毛利標「理論上界」，不是有限訂單保證可達值；無上限折數券維持固定折讓比例。
5. 各滿件折數各自計算所有券，互斥券不相加，不推定訂單只買門檻件數。取精確結果極值後才顯示舍入。
6. 百分比費用以優惠後含稅商品價為基礎，每個費目各自套最低／最高；固定費與勾選運費按單件扣除。費用金額按賣家支出計入，不自動拆可扣抵費用稅額。上述簡化約定在設定畫面明示，不引入使用者已刪除的進階欄位。
7. 未稅收入＝折後含稅價÷1.05；費用後貢獻額＝未稅收入−主檔淨成本−基本費用−（第二欄活動費用）−勾選運費。比率以折後未稅收入為分母。沿用 Worker BigInt 有理數與主檔三種成本稅別，最終金額／百分比才舍入至兩位小數；零收入比率為空值，負值保留。

## 權限、版本與備份

閱讀要求 ITEMS＋ITEMS_COST_MARGIN；只有商品權限者成本及稅別保持空白，整個毛利不顯示且不呼叫毛利／規則接口。後端同樣拒絕無權限讀取。平台共用設定依既有結構設定權限限 SUPER_ADMIN 寫入；沒有新增自動授權。

0071 migration 新增目前規則與不可覆寫的歷史版本兩表，使用既有平台id。PUT 帶 revision，current＋version＋Audit 同批原子寫入；版本落後回409且不留下部分歷史。Audit 只列前後版號，完整前後規則由歷史表保留，避免泛用 Audit 混入成本／毛利。設定儲存即生效，沒有排程。舊備份升級時新表為空，不虛構真實費率。

有界讀取所選商品的適用平台規則，一次 JSON1 查詢，不逐券查D1；平台名稱一次查詢。每平台每類費目與滿件各最多100筆、券最多500張，避免無界同步運算。規則變更事件讓商品 owner 重讀同次詳情與毛利。這些手動 UI API 仍沿用 CYID Session，不是 AI 接口；本階段沒有 AI 委派、MCP、費率查證或審核流程。

## 驗收與發布界線

自動驗證涵蓋600／799、封頂、相同門檻、最後理論界、無上限折數券、兩費率情況、運費、三折數×全券、零／負毛利、權限、revision、歷史、備份與單一商品讀取。實際1440／390畫面仍待能啟動瀏覽器的環境目視，不能以元件測試冒充截圖。

每次修改均須 handoff，交 Claude 審查。正式 D1 未讀寫、未執行遠端 migration，未合併／部署；CI成功不構成發布授權。

網路費用後結果型別為`ContributionValue`（`contributionAmount`／`contributionMarginPercent`），與原商品基本毛利`MarginValue`（`grossProfit`／`grossMarginPercent`）明確區分，畫面仍以「毛利」方便閱讀；兩者共用同一精確計算核心。

## V0.20.1 品類費率（使用者後續定案）

蝦皮、Mo+各自設定品類費率，商品詳情新增「蝦皮品類」「Mo+品類」選填下拉。選項只列對應平台已儲存的品類；尚未設定時停用下拉並提示先設定。兩平台不可互選；商品一般分類與兩個平台品類彼此獨立，不自動對應、不預選。

平台未選品類時，**只有該平台的毛利數字／區間不顯示**，改提示「請先選擇品類」。未選蝦皮不影響Mo+、其他平台及門市／診所／批發；Mo+同理。所選品類費率僅加一次至基本費率，因此兩種費率欄都包含它；不把全部品類費率加總。品類改名保留穩定識別及商品關聯；已使用品類須先調整商品才能移除。

品類費率沿用平台設定revision／版本／Audit原子保存。商品的品類選擇隨既有商品revision保存；省略欄位維持原選擇，明確空陣列才清空。後端與資料庫均驗證平台／品類對應，設定與商品並發修改不留下部分異動。0072新增品類鍵投影及商品關聯兩表，不複製商品價／成本；費率及名稱仍由rules_json唯一管理。舊0071／0070備份新表為空，舊規則無categoryFees時讀為空清單，不猜品類。

既有platforms API附每平台feeCategories（只有id／name），一般商品使用者可選品類，不因此取得費率金額、成本或毛利；管理費率仍限SUPER_ADMIN、毛利仍要求ITEMS_COST_MARGIN。平台固定身分沿用0061既有蝦id1、MO id2，使用可改名的name不作識別鍵。
