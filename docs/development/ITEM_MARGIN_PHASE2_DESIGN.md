## 1. 目標與資料來源

在既有毛利分析加入各平台的網路基本毛利及費用後獲利試算，能說明每筆費用、優惠和有效情境，並由受控 AI API 協助管理規則。

| 資料 | 唯一來源／可否於分析頁輸入 |
| --- | --- |
| 商品成本、成本稅別、單位及換算 | 商品主檔，唯讀，不另填／覆寫 |
| 各平台商品售價 | 既有 item_online_prices／item_web_platforms，固定含稅解讀，唯讀 |
| 手續費、優惠、物流補貼及其他銷售費用 | 平台共用規則，可依授權新增／修改／停用 |
| 試算商品與數量、日期、賣家資格／方案 | 試算條件；不修改商品主檔 |
| 過往試算的成本／價格 | 僅使用者保存試算時凍結唯讀收據，不是另一份可編輯主檔 |

不預先填任何平台真實費率；手續費缺資料時僅顯示基本毛利及「費用待設定」。無官方來源的估算不成為正式費率。

## 2. 畫面提案

### 2.1 商品詳情與毛利同頁；費用管理建議放設定按鈕

依使用者本輪方向，商品詳情與毛利分析放在同一畫面，上方維持既有商品資料，下方直接呈現唯讀毛利摘要／通路比較及網路結果；不將毛利分析拆成獨立同層頁籤，也不再需要「商品資料／毛利分析」切換。瑕疵維持獨立功能入口。

平台費率及優惠是跨商品共用設定，建議放進既有「商品模組設定」按鈕：增加「平台費用與優惠」管理項目，內分費率、優惠、物流／其他費用、待審提案與歷史。沿用現有平台名單，不建立第二份平台。這個設定入口建議待使用者確認；不增加新的主要「平台費率」頁籤。

毛利區只提供閱讀、平台切換、情境條件及查看計算／規則明細，不擺共用規則編輯表單。管理者可從規則明細前往同一設定入口，帶入目前平台；畫面須標明會影響的平台／分類／商品範圍。

資料與查詢責任：

- 沿用 ItemOperationalPage 的選定商品與已儲存資料，由同一載入／更新 owner 提供商品區及毛利區；不另建商品選取 state 或第二次詳情查詢。
- 後端擴充既有商品詳情讀取：一次取得權威商品 aggregate，供同一 Worker 核心算成本、各通路及預設網路情境，授權時將派生結果隨同商品資料回傳；前端不自算、不重新傳入成本／售價覆寫。
- 當次所需的有效費率／活動依平台及版本有界讀取一次，在記憶體重用，不為每個情境重查商品或費率。不為唯讀毛利另外 mounted 一個重新載入商品的元件／輪詢。
- 商品儲存、規則更新或試算條件改變時才按需更新。搭購／進階試算的 API 仍須驗證目前商品 revision、權限及規則版本，必要的權威重讀不冒稱零查詢；回應同時更新兩區，不各自重抓。
- 無 ITEMS_COST_MARGIN 時成本及稅別原位置留白，整個毛利區不掛載、不請求規則；直接 API 仍拒絕，不靠前端傳旗標取得派生結果。

## 3. 試算條件與區間定義（待確認項目 B）

預設「選定商品1件、沒有搭購商品、今天、目前選取賣家方案」。標準情境先不使用可選優惠，必收平台費仍計入；使用者可指定常用優惠作為自己的標準情境。它不是購買頻率統計或自動推測的平均客單。

進階情境可改數量，或從同平台的商品主檔選擇搭購商品與數量。每件售價仍讀主檔；系統自動得到訂單金額、符合活動的商品金額及數量，不能手填或覆寫選定商品的售價／成本。其他商品缺同平台售價或適用條件時顯示缺資料，不猜金額。

區間只比較此訂單條件下的合法活動組合：

- 最佳：有效組合中貢獻利率最高；同時列獲利額。
- 標準：使用者指定的活動組合，未指定採上述預設。
- 最差：有效組合中貢獻利率最低；同時列獲利額。
- 顯示範圍、件數、日期、賣家方案、規則版本與完整度，不能宣稱涵蓋所有可能客單。
- 單品1件未達滿999就不能扣滿999券；改多件或加入搭購後重新判斷。
- 活動門檻、計算順序、互斥、可併用、上限、賣家分攤及期間須完整，不能把所有優惠直接加總。
- 條件不足時標「已知規則試算」或「待確認」，沒有費率不能用零費率假裝已算完。零費率須為明確設定。

## 4. 計算順序與公式

1. 從同一商品主檔快照取得各品項成本、稅別、價格、分類、數量與單位；引用revision。
2. 按試算時間、平台、賣家方案、分類／商品取得已核准且有效的費率及啟用活動版本。
3. 依活動的門檻基準、計算順序、適用商品及互斥／依賴條件列出合法組合。
4. 拆開賣家折讓、平台出資優惠及實際補貼；以平台規則決定賣家實際商品收入，不能把平台出資全算成賣家負擔。
5. 依每項費用自己的計費基礎、上下限、取整順序及稅務條件，算賣家負擔的費用淨額；不能把所有費用一律除1.05。
6. 訂單折扣及固定每單費用按指定規則分攤到品項；建議預設按活動前的適用品項金額比例。以最小貨幣單位分配，餘數依固定順序補齊，確保各品項加總等於整單。官方規則不同時明確設定覆寫。
7. 算指定商品的收入、成本、費用及貢獻額／率；以比率取極值，不按費用高低猜最佳最差。

定義：

- 基本毛利率＝（主檔含稅售價÷1.05－商品淨成本）÷（主檔含稅售價÷1.05）。沿用使用者指定的一般應稅前提及第一階段核心。
- 情境貢獻額＝情境實際未稅商品收入－對應數量淨成本－分攤銷售費用淨額。
- 貢獻利率＝情境貢獻額÷情境實際未稅商品收入。
- 賣家折讓已反映於收入，不再在費用重扣；平台補貼的收入／稅務歸屬須有已確認規則，未知時不冒用扣抵或收入假設。
- 毛利計算金額使用第一階段精確有理數；平台規則要求的每步取整先按該規則執行，最後畫面顯示兩位。零收入比率為—、負貢獻保留並警示。

純合成驗算例：淨成本100、主檔含稅售價210、固定淨費用10；可選券為滿210折21、全由賣家負擔、不可疊加。未用券：淨收入200、基本毛利率50%、費用後45%。用券：淨收入180、貢獻額70、費用後38.89%。指定此單品1件時區間38.89%～45%。這不是任何平台真實費率，也不將21再扣一次。

## 5. 費用與活動資料設計

沿用既有平台id、商品／分類與網路售價；新資料只保存規則、提案、版本及選擇保存的試算收據。實際表名／migration編號在實作前依最新schema確定。

| 類別 | 第一版需要的欄位 |
| --- | --- |
| 平台手續費 | 費目、固定／比例、計費基礎、上下限、取整、費用稅別及扣抵條件、平台／商品／分類／賣家方案、起迄、來源／查證日期、審查狀態、版本 |
| 優惠活動 | 名稱、固定券／百分比／滿額／滿件、門檻基準、折扣上限、平台與賣家負擔、適用範圍、互斥群組／可併用及依賴條件、順序、日期、啟停、來源、版本 |
| 物流及其他費用 | 賣家實付／補貼、每單或每件、適用條件、分攤、稅務與生效版本 |
| 費率提案 | 來源、新舊版本差異、生效範圍、代表商品影響、提案者、待審／通過／退回、審查理由與版本 |
| 試算收據（明確保存時） | 當次商品與規則版本、凍結輸入、訂單內容、逐項明細及結果；唯讀，不是第二份價格主檔 |

同一費目／同一計費槽的覆寫順序建議「指定商品＞分類＞平台共用」，不同費目可同時計收。重疊同層規則不能靠最後修改時間默默挑一筆，需在儲存時解決衝突。生效版本不可覆寫，修改新增版本；停用不刪歷史。

時間採台北時區；表單日期若為含結束日，後端轉成「起日00:00含、結束日次日00:00不含」。查詢當下判斷失效，無需替每個活動加獨立排程。

費率提案的影響先比較目前選定商品及指定代表情境；完整受影響商品比較採使用者啟動、分頁／分批作業，不在每次開視窗全商品重算。保存收據、讀取成本與影響結果都受成本／毛利權限；Audit只記規則變更與識別，不把商品成本／試算明細寫進可被其他人讀取的泛用Audit。

## 6. 權限與 AI 操作

### 6.1 人員管理範圍（待確認項目 C）

建議沿用 ITEMS＋ITEMS_COST_MARGIN 作查看／試算門檻；費率、優惠等平台共用設定先限SUPER_ADMIN管理及核准，與既有平台設定權限方向一致。無新增自動授權。若要交員工管理，使用者先指定範圍，再決定另加管理次級權限；不因能看毛利就能修改影響全平台的規則。

### 6.2 既定核准差異

- 優惠：使用者明確授權、內容完整，AI試算後可經受控API套用；缺平台、起迄、門檻基準或賣家負擔等必要資料時回待補，不猜日期或比例。
- 費率：AI查官方公告、附來源／生效條件、比較差異，只能建立待審提案；人工核准才生效。AI本身沒有核准費率能力。
- 口述「下週開始、月底結束」以台北日期解析，預覽時顯示實際起迄日期，存明確日期而不是保留相對文字。

### 6.3 接口與身分

先建REST contract，再按需要包MCP：讀商品／規則、建優惠草稿、preview、明確授權apply、提費率變更、人工review、查版本／結果。全部透過Worker service，不提供D1憑證。

AI身分採綁定既有CYID人員／workspace且可撤銷的專用委派憑證／scope；正式實作前核對CYID已支援的server contract，不自行接受AI聲稱的人員身分，不挪用社群小編token或抽取browser session。scope僅preview／promotion.apply／fee.propose等必要動作，實際權限不得超過目前綁定人的權限；停用／撤權後失效。人工費率核准只用既有登入者權限。

每個寫入帶expectedRevision與重複請求識別；preview綁商品revision、規則版本、訂單條件與試算時間，資料變更後舊預覽不得直接套用。共用Audit記前後規則、操作者／委派者、來源、授權識別及生效時間。通知只借用既有適合的站內／BOT通知能力，不把費率審核變成社群發文審核。
