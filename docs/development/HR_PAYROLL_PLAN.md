- 日期：2026-11-15（台灣）。狀態：需求確認中，尚未實作薪資核心、資料表或授權入口。
- 基準：第二批 PR #517，`1d6e9974dff1181b5b2735fc0de15af79dd69d2f`；分支 `cyweb/hr-payroll-rules-20261115`。
- 使用者直接交辦第三批；延續共用元件、表格式介面、同一資料與計算來源。全部變更寫 handoff 交 Claude 審查，不合併、不部署。
- 此文件記錄本次需求與提案，不取代尚未實作的正式 API／薪資契約。已上線行為以 [HR_MODULE_CONTRACT](../architecture/HR_MODULE_CONTRACT.md) 為準。

## 已確認的公司規則

| 項目 | 使用者確認內容 |
| --- | --- |
| 發薪日 | 次月 5 日；遇假日的處理未定 |
| 月薪折算 | 一律以 30 天為基準；月中到離職、跨月日期與舍入細節仍需列實例確認 |
| 津貼 | 由使用者自行新增；沿用原津貼類型及員工薪資紀錄，不預建一份重複薪資主檔 |
| 全勤適用 | 不是每個人都有，每位員工可勾選是否適用；未指定統一金額，不寫死金額，也不自動把所有員工勾選 |
| 遲到寬限 | 按單次判斷，不按整月累計；1～5 分鐘不扣薪、不扣全勤 |
| 遲到扣發 | 單次 6 分鐘起，按全部實際遲到分鐘扣薪，同時不發當月全部全勤；6 分鐘扣 6 分鐘，並非扣 1 分鐘 |
| 早退 | 無 5 分鐘寬限；早退幾分鐘就按幾分鐘扣薪，並不發當月全部全勤 |
| 一般事假／曠班 | 不發當月全部全勤；法定受保護假別不得因併入事假額度而套用此規則 |
| 普通病假 | 全勤依病假時間按 30 天比例扣發；這是全勤規則，不等於已決定病假本薪給付方式 |
| 生理假 | 不扣全勤，即使其日數併入病假額度仍保持此保護 |
| 誤打下班卡 | 由使用者或其指定、明確授權的管理員人工更正為實際正確下班時間；系統不自動當作誤打卡、不自動補成排定下班時間 |
| 法令底線 | 不確定時查現行官方法規；公司可提供較優條件，不得低於適用法定保障 |

遲到門檻以最後確認的「超過 5 分鐘（6 分鐘起）」為準，取代前述對話中「5 分鐘以上」的暫定解讀。全勤按月最多扣至零；不同違規及病假同月發生，列明實際全扣或比例扣原因，不重複扣成負數。

## 法規查核與必須保留的例外

查核日為 2026-11-15，依勞動部現行條文、函釋及問答，不僅查《勞動基準法》名稱。正式實作／發布前需再核對有效版本及適用條件。

1. 《勞工請假規則》第 9 條：普通病假全勤按比例扣發；婚假、喪假、公傷病假、公假、妊娠未滿三個月流產未請產假之普通病假，以及依法親自照顧家庭成員的事假，均有不得影響全勤的保障。
2. 《性別平等工作法》第 21 條：生理假、家庭照顧假等法定受保護請求不得被視為缺勤影響全勤。保護清單以適用條文建立，不能只排除生理假或只比對畫面顯示名稱。
3. 勞動部 115 年 1 月 9 日勞動條 2 字第 1140149454 號函：以小時請普通病假，全勤扣發額按 `全勤金額 ÷ 30 ÷ 8 × 病假時數`；實作保留分鐘精度，相當於再除以 60 乘病假分鐘。舍入至元的時間點仍待確認。
4. 勞動部新制問答 Q7：病假以外已約定之全勤扣發原因須明確、可舉證，不得以病假包裝成其他扣發原因。Q10 另說明實發全勤與月工資計算的關係；不得直接以「本薪」取代所有適用工資基礎。
5. 月薪及寬限規則不直接套到所有時薪／不排班兼職。時薪實際計薪、公司寬限優惠與全勤適用須在下一輪定清楚；法定保護不能因僱用型態而略過。

## 人工更正、資料與授權設計提案

目前出勤已能由超級管理員在原表修改，使用同一 `HrAttendanceService.put`，有 revision、交易及更動前後 Audit；`worker/http/hr-routes.ts` 目前所有人事 API 仍限 SUPER_ADMIN。一般 ADMIN 現在沒有更正權限，本規劃不宣稱已開放。

- 延用原出勤表格就地更正，顯示實際輸入及有效值，不另建第二套打卡來源或薪資人員手填的出勤分鐘。
- 更正須有原因，保留更正前後時間、操作者及時間、revision，延用共用 Audit。只把誤打卡修為實際時間，不等於豁免真實早退。
- 使用者明確要求可授權指定管理員更正；具體授權名單、員工／門市範圍及入口仍待確認。不得因 ADMIN 身分就可更正所有人，也不得因此取得薪資、身分證或全部人事權限。
- 權限須由 Worker 驗證，不能只顯示／隱藏按鈕；既有月出勤 API 也可改加班，不能把該 API 整體放行作為「只可更正下班時間」。實作須設計與現有 CYID／本地授權相容的最小能力，而非另建登入或直接寫 D1。
- 出勤更正後由同一後端薪資核心更新尚未確認的薪資結果。已確認／已發薪結果不得靜默重寫；撤回重算或次月補扣的流程須先定案。
- 有效請假已排除的區間不再計遲到／早退。缺卡、未完成假單、無法判定的出勤須列待確認，不直接猜成曠班扣薪或自動修成正常。
- 第二批仍可顯示實際遲到 1～5 分鐘；新薪資核心分別計算「實際分鐘」「計薪扣款分鐘」「全勤原因」，不可把真實出勤紀錄改為零來實現寬限。

## 尚待確認，不可猜測的薪資規則

| 類別 | 尚缺的決策 |
| --- | --- |
| 計薪日期 | 明確起迄、發薪日遇假日、未滿月 28／29／31 日案例與留停、月中調薪分段 |
| 工資基礎 | 月薪／時薪各種扣款及加班的工資組成、津貼的實際給付規則、全勤金額及生效歷史；不得僅憑津貼名稱／是否經常性就猜法律性質 |
| 請假給薪 | 依法給付的各假別與公司較優待遇；普通病假本薪與生理假給薪尚未詢問，不能因全勤規則直接推定 |
| 加班／結清 | 延用已確認加班費／補休選擇；日型、連六公司優惠、補休到期及特休未休工資的實作口徑與歸屬月份 |
| 保險及扣繳 | 勞健保、就保、職災、勞退、自提、眷屬、稅額／身分及生效級距的維護範圍；官方查核後呈列方案，不寫死估計費率 |
| 確認與更正 | 薪資草稿、確認、發薪及確認後更正方式，指定管理員更正出勤的具體授權範圍 |
| 金額精度 | 內部精確計算、逐項／月底舍入及尾差分配方式；不得先逐分鐘舍入而放大扣款 |

## 規則齊備後的執行順序

1. 完成上述決策與官方法源對照，以虛構員工／薪資列可核算範例，交使用者確認公司未定事項。
2. 建立單一 Worker 薪資核心及來源快照／規則版本契約；前端不維護第二套公式，成本與查詢有界，避免逐人逐日 N+1。
3. 依既有 schema 決定必要 forward migrations、薪資單生命週期及備份還原範圍；保留既有主檔薪資／津貼及出勤權威。
4. 套用共用 DataViewToolbar、RecordSheet／RecordRows、EntryTable／Dialog，在現有薪資頁表列月份與明細，沿用 820px 單一資料狀態；確切分頁與操作待完整方案確認。
5. 實作出勤更正及最小權限；涵蓋未授權拒絕、逾期請求、revision 競態、寫入失敗保留與 Audit。不得以開放所有 HR API 代替指定授權。
6. 驗證邊界、月底精度、已確認薪資保護、權限與交易、隔離 D1／備份，以及 1440／390 實際目視；每輪更新同分支 handoff 交 Claude 審查，不合併／部署。

預定驗收案例包含：單次 5 分鐘零扣款／全勤不變、6 分鐘扣 6 分鐘且全勤歸零、多次各 3 分鐘不累計全扣、早退 1 分鐘扣 1 分鐘且全勤歸零、依法核准假與休息區間不重扣、生理／家庭照顧與保護假別全勤不變、普通病假按比例、多人有／無全勤分開、同月多原因全勤不重扣、更正誤打卡後草稿更新及已確認結果不靜默改寫。這些是未實作的驗收規格，不是已通過測試。
