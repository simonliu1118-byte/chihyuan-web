## 已確認的公司規則

| 項目 | 使用者確認內容 |
| --- | --- |
| 發薪日 | 公司目前於次月 5 日發薪，遇假日順延下一個工作日。此為公司慣例，不是自動排發薪的需求；本批不建銀行工作日日曆、不自動排匯款或以順延規則作為薪資計算前置條件，僅保留實際發薪日紀錄 |
| 月薪折算 | 一律以 30 天為基準；月中到離職、跨月日期與舍入細節仍需列實例確認 |
| 津貼 | 由使用者自行新增；沿用原津貼類型及員工薪資紀錄，不預建一份重複薪資主檔 |
| 全勤適用 | 不是每個人都有，每位員工可勾選是否適用；未指定統一金額，不寫死金額，也不自動把所有員工勾選 |
| 遲到寬限 | 按單次判斷，不按整月累計；1～5 分鐘不扣薪、不扣全勤 |
| 遲到扣發 | 單次 6 分鐘起，按全部實際遲到分鐘扣薪，同時不發當月全部全勤；6 分鐘扣 6 分鐘，並非扣 1 分鐘 |
| 早退 | 無 5 分鐘寬限；早退幾分鐘就按幾分鐘扣薪，並不發當月全部全勤 |
| 一般事假／曠班 | 不發當月全部全勤；法定受保護假別不得因併入事假額度而套用此規則 |
| 普通病假 | 全勤依病假時間按 30 天比例扣發；請假期間工資依適用法定標準，不另設定公司全薪優惠 |
| 生理假 | 每月額度 1 日，可拆成兩個半天；同樣適用半小時最小單位，按實請時數扣額度，不強制整日或整個半日、也不因拆單增加月額度。不扣全勤，即使其日數併入病假額度仍保持此保護；工資依適用法定標準 |
| 請假最小單位 | 使用者確認所有假別最小半小時，保留既有半小時時數驗證；此為輸入／分次單位，不改變法定連續假期、曆日計算或各假別總額度 |
| 其他假別給薪 | 依現行適用法定標準，包含《勞基法》、《勞工請假規則》與《性別平等工作法》等；不再把是否公司給全薪列為未定問題 |
| 保險、勞退與扣繳 | 第三批一起自動計算，不改為每月人工輸入保費／扣繳額 |
| 官方表年度更新 | 每年必須自動導入新級距金額表；包含相依費率、負擔／扣繳規則的生效版本，不能只換級距數字而沿用失效費率。更新舊月份時仍使用其適用歷史版本 |
| 誤打下班卡 | 由使用者或其指定、明確授權的管理員人工更正為實際正確下班時間；系統不自動當作誤打卡、不自動補成排定下班時間 |
| 法令底線 | 不確定時查現行官方法規；公司可提供較優條件，不得低於適用法定保障 |

遲到門檻以最後確認的「超過 5 分鐘（6 分鐘起）」為準，取代前述對話中「5 分鐘以上」的暫定解讀。全勤按月最多扣至零；不同違規及病假同月發生，列明實際全扣或比例扣原因，不重複扣成負數。

## 法規查核與必須保留的例外

查核日為 2026-11-15，依勞動部現行條文、函釋及問答，不僅查《勞動基準法》名稱。正式實作／發布前需再核對有效版本及適用條件。

1. 《勞工請假規則》第 9 條：普通病假全勤按比例扣發；婚假、喪假、公傷病假、公假、妊娠未滿三個月流產未請產假之普通病假，以及依法親自照顧家庭成員的事假，均有不得影響全勤的保障。
2. 《性別平等工作法》第 21 條：生理假、家庭照顧假等法定受保護請求不得被視為缺勤影響全勤。保護清單以適用條文建立，不能只排除生理假或只比對畫面顯示名稱。
3. 勞動部 115 年 1 月 9 日勞動條 2 字第 1140149454 號函：以小時請普通病假，全勤扣發額按 `全勤金額 ÷ 30 ÷ 8 × 病假時數`；實作保留分鐘精度，相當於再除以 60 乘病假分鐘。舍入至元的時間點仍待確認。
4. 勞動部新制問答 Q7：病假以外已約定之全勤扣發原因須明確、可舉證，不得以病假包裝成其他扣發原因。Q10 另說明實發全勤與月工資計算的關係；不得直接以「本薪」取代所有適用工資基礎。
5. 月薪及寬限規則不直接套到所有時薪／不排班兼職。時薪實際計薪、公司寬限優惠與全勤適用須在下一輪定清楚；法定保護不能因僱用型態而略過。
6. 2026-11-15 補充確認：生理假依《性別平等工作法》第 14 條每月 1 日，併入與不併入病假的工資均減半發給，並依第 21 條保留全勤。公司接受拆兩個半天及半小時單位，系統依時數累積額度，不能以假單筆數或不同日期筆數直接當作已用日數；年度前 3 日不併病假的邊界亦以實際額度換算，避免拆單後誤併。
7. 普通傷病假依《勞工請假規則》第 4 條，一年內未超過 30 日部分工資折半；超過、住院、安胎、勞保傷病給付補足及公傷等各依法定條件區分，不把所有名稱含「病」的假一律半薪。
8. 產假及流產產假仍須按法定適用期間依曆連續計算，適用《勞基法》的工資另依受僱是否滿 6 個月及流產階段判定。半小時輸入精度不代表可把法定連續產假拆成零碎時段，更不能排除其間休息日／假日；同樣不能將月薪 30 天分母套成產假天數。育嬰留職停薪則依其期間及按日申請規定處理，不與一般時段假混為一種；此處僅記錄法定邊界，未新增育嬰留停申請／補助功能。

## 人工更正、資料與授權設計提案

目前出勤已能由超級管理員在原表修改，使用同一 `HrAttendanceService.put`，有 revision、交易及更動前後 Audit；`worker/http/hr-routes.ts` 目前所有人事 API 仍限 SUPER_ADMIN。一般 ADMIN 現在沒有更正權限，本規劃不宣稱已開放。

- 延用原出勤表格就地更正，顯示實際輸入及有效值，不另建第二套打卡來源或薪資人員手填的出勤分鐘。
- 更正須有原因，保留更正前後時間、操作者及時間、revision，延用共用 Audit。只把誤打卡修為實際時間，不等於豁免真實早退。
- 使用者明確要求可授權指定管理員更正；具體授權名單、員工／門市範圍及入口仍待確認。不得因 ADMIN 身分就可更正所有人，也不得因此取得薪資、身分證或全部人事權限。
- 權限須由 Worker 驗證，不能只顯示／隱藏按鈕；既有月出勤 API 也可改加班，不能把該 API 整體放行作為「只可更正下班時間」。實作須設計與現有 CYID／本地授權相容的最小能力，而非另建登入或直接寫 D1。
- 出勤更正後由同一後端薪資核心更新尚未確認的薪資結果。已確認／已發薪結果不得靜默重寫；撤回重算或次月補扣的流程須先定案。
- 有效請假已排除的區間不再計遲到／早退。缺卡、未完成假單、無法判定的出勤須列待確認，不直接猜成曠班扣薪或自動修成正常。
- 第二批仍可顯示實際遲到 1～5 分鐘；新薪資核心分別計算「實際分鐘」「計薪扣款分鐘」「全勤原因」，不可把真實出勤紀錄改為零來實現寬限。

### 自動導入與生效流程

1. 共用排程：沿用 `shared/cyweb-cron.ts`／`worker/index.ts` 的唯一排程分派，增加每日一次的有界官方檢查及失敗重試，不另加一套每分鐘全量抓表。以台灣時間處理年度切換；年底預抓下一年度，也檢查年中生效公告。具體每日時段於實作選定，避免與備份任務爭用。
2. 來源白名單：僅抓勞保局／勞動部、健保署、財政部與其公告列出的政府開放資料；檢查每次重新導向的目標、大小／逾時限制，防止可輸入任意網址的後端代理。不以 AI／搜尋摘要推估表格或直接寫 D1。
3. 原文與正規化版本：保留來源網址、公告年度／文號、生效起迄、檔案 hash、抓取時間、解析器版本與驗證結果；正常化表格有唯一版本，公開來源原檔保存於核准的 Storage 並納入備份設計，不能混入員工資料。
4. 驗證：核對官方年度與生效日、欄位及所有列數／級數、各身分類別、金額單位、級距連續與無重疊、數值合理性、扶養欄數、費率／負擔關係，以及官方範例與前版差異。民國日期明確轉換；`元以下`、上限以上、特殊低薪身分等不能用模糊字串拆解後遺漏。
5. 自動套用：官方來源明確、資料完整及確定性驗證通過即自動新增有效版本，未來生效表先保存待日期到達。正常年度更新不要求使用者每年按核准；同內容重跑不重複建版本／Audit，多任務併發以唯一鍵與交易防護。
6. 異常：格式改版、年度不明、缺表、來源間矛盾或生效資料缺失，標示待處理並通知有權管理者，不能猜數字、自動套用不完整版本或把缺值當零。仍在有效期且未被新制取代的現行版本可繼續使用；已知新制生效而資料未齊時，阻止確認受影響薪資並顯示原因，不靜默沿用舊表。
7. 歷史：按各項適用的法定期間／日期挑選表版，薪資所屬月、保險期間與實際給付日分開保存，跨年次月 5 日發薪不得把全部項目都只用薪資月份的年度判斷。薪資結果保留輸入及表版快照；新表不覆寫歷史，也不靜默重算已確認／已發薪資料。
8. 介面：在現有人事設定用共用表格顯示項目、版本、生效日、來源、最近檢查、匯入狀態、差異與歷史；授權者可手動重試同一匯入 Service，保留來源驗證與 Audit，不能另開任意改法定費率的無來源入口。

### 每人資料與計算界線

- 員工只需維護有生效日的投保／適用身分、核定投保／提繳基礎、健保計費眷口、勞退自提與扣繳選擇／申報資料等。這些不是每月手填計算結果；缺必要資料列待補，不預設每個人都無眷屬、都適用就保或都用相同扣繳方式。
- 法定級距自動更新與員工已申報投保資料異動是不同事件；不因更新表格就自行代報加退保或宣稱政府已核定。投保基礎與工資有差異應提示依法調整／申報，需區分法定自動調整與尚待申報的員工異動。
- 薪資明細分列勞保、就保、健保、個人自提與扣繳；雇主負擔／雇主勞退分開列為公司成本，不混成員工扣款。職災等另須依行業／單位適用費率處理，不把一般級距直接當所有費率。
- 各項保費、提繳與稅額的舍入、部分月、身分及免扣條件依各自規定處理，不能把公司 30 天折算規則不加區別套到健保／扣繳所有情境。全年所得稅結算不是每月扣繳，不以年度綜所稅級距表取代薪資扣繳表。
- 本次納入的是薪資計算及規則資料自動更新；沒有自動向政府送件、申報／繳款或代發薪資的授權。
